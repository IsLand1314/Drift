# Drift 面板视觉设计

这份文档记录 Drift 终端交互的视觉约定、调整原因和后续面板设计方向。以后涉及输入提示、回答展示、状态面板、颜色、分隔线、缩进和耗时信息的调整，都先在这里记录，再同步到对应阶段文档。

## 1. 设计目标

Drift 的终端输出需要让用户一眼分清：

- 当前正在输入什么；
- 哪些内容是模型回答；
- 哪些内容是本地命令反馈；
- 当前会话和上下文处于什么状态；
- 哪些数字是估算值，哪些数字来自 Provider 的真实数据。

设计参考 FoxCode 的终端体验，但不复制其完整 TUI。M1.8 起，真实终端已引入最小输入组件来控制单行输入；非终端继续只采用标准输出与纯文本输入。

## 2. 当前交互样式

### 2.1 输入提示

真实终端使用青色提示符：

```text
────────────────────────
❯ 请输入问题
```

非终端输出不写入 ANSI 控制字符，使用普通的 `> ` 作为兼容提示符。

普通文本命令不会发送给模型：

```text
status  -> 如需查看状态，请输入 /status
clear   -> 如需清空上下文，请输入 /clear
compact -> 如需压缩上下文，请输入 /compact
```

### 2.2 助手回答

助手回答使用独立标记，并在回答结束时显示本轮耗时：

```text
● 这是 Drift 的回答内容。

Completed · 2.4s
```

- `●` 使用紫色或洋红色；
- 回答正文使用默认前景色；
- 完成耗时使用暗灰色；
- 非终端输出保留纯文本标记，不输出 ANSI 控制符。

## 3. `/status` 状态面板

正式命令为 `/status`，不再保留 `/stats` 兼容命令。

当前布局：

```text
Drift Status
────────────────────

  Session ID:  conv-c57d13e4056f99b83306b787
  Model:       deepseek-v4-flash
  Context:     100% remaining
               2.3 KB used / 1048.6 KB total
  Tokens:      17 in / 9 out
  Tools:       3 enabled
  Workspace:   F:\code\drift
```

### 3.1 对齐规则

- 所有字段统一缩进两个空格；
- 字段名使用固定宽度，值从同一列开始；
- `Context` 的第二行对齐到值列；
- 分隔线长度与面板标题或内容宽度保持协调；
- 状态面板不输出用户提示词、文件内容或 Provider 密钥。

### 3.2 颜色规则

| 元素 | 建议颜色 | 说明 |
| --- | --- | --- |
| `Drift Status` | 蓝色/青色 | 面板标题 |
| 字段名 | 暗灰色 | `Session ID`、`Model` 等标签 |
| 普通值 | 默认前景色 | 会话 ID、模型名、工具数量 |
| `Workspace` | 青色 | 强调当前工作目录 |
| `Tokens: unavailable` | 暗黄色/暗灰色 | 表示 Provider 尚未返回真实 usage |
| 分隔线 | 暗灰色 | 降低视觉干扰 |

### 3.3 字段边界

当前显示：

- `Session ID`：当前完整会话 ID；临时模式显示 `temporary (not saved)`；
- `Model`：当前配置的模型名；
- `Context`：Drift 根据消息结构计算的字节估算，使用十进制 KB；
- `Tokens`：显示 Provider 返回的真实输入/输出 token；未返回时显示 `unavailable`，混合状态追加 `(partial)`；
- `Tools`：已注册的只读工具数量；
- `Workspace`：当前 workspace 根目录。

暂不显示 `Memory`，因为当前项目没有独立长期记忆系统；会话快照不能直接等同于 Memory。

## 4. M1.8 输入框视觉约定（已实现）

真实终端的空闲输入区应当明确可见，而不是只有一个裸提示符：

```text
────────────────────────
❯ Send a message...
  Enter 发送 · Ctrl+C 取消                         deepseek-v4-flash
────────────────────────
```

- 上下分隔线为暗灰色；`❯` 为青色；占位文本为暗灰色；
- 用户开始输入后，占位文本消失，输入文字使用默认前景色，光标由输入组件控制；
- 输入框下方左侧显示灰色操作提示，右侧显示当前模型名，并按终端宽度右对齐；
- Enter 提交后，输入区清空并在下一次等待时重新显示占位文本；
- 输入框底部边界由输入组件统一绘制，下一轮顶部边界不得重复输出；
- 模型回答仍使用 `●` 和 `Completed · <耗时>`，不把输入框升级为全屏聊天界面；
- 流式/工具轮被 Ctrl+C 取消时显示红或紫色 `✖ 当前轮已取消；会话仍可继续`，不显示原始 `context canceled`；
- 空闲输入时 Ctrl+C 仍退出 chat（退出码 130）。

`/status` 不跟随 FoxCode 的全灰风格：Drift 保留目前的语义颜色，确保 workspace、真实 Token、未知状态在视觉上仍有区分。

## 5. 当前已知限制

M1.7 及以前的 chat 使用 `bufio.Scanner` 按行读取输入，因此只能控制提示符和输出布局，不能完整控制用户输入中的光标、上下历史、多行编辑和输入框重绘。M1.8 的最小输入组件已解决占位符、受控光标与单行重绘；它不解决完整的历史、多行或 viewport。

如果未来要完全复刻 FoxCode 的输入区域，需要单独引入终端行编辑或 TUI 层，处理：

- 原始终端模式；
- 光标移动；
- 上下历史；
- 多行输入；
- 输入区域重绘；
- Windows Terminal、Linux TTY 和重定向输出的兼容。

这不属于当前 M1.4 的轻量视觉优化范围。

## 6. 人工验收清单

在项目根目录运行：

```powershell
go run ./cmd/drift chat -w .
```

依次输入：

```text
/status
status
clear
compact
你好，介绍一下你自己
exit
```

检查：

1. `/status` 显示英文状态字段，并且字段值对齐；
2. Context 第二行与其他值列对齐；
3. `status`、`clear`、`compact` 只显示命令提示，不触发模型请求；
4. 普通回答前有助手标记，结束后有 `Completed · <耗时>`；
5. 真实终端能看到颜色和分隔线；
6. 将输出重定向到文件时，不出现 ANSI 控制字符；
7. `Tokens: unavailable` 不被误认为真实 Token 用量。

## 7. 后续调整计划

按优先级排列：

1. 完成 M1.8 的最小输入框和取消提示；
2. 根据实际使用频率决定是否增加 `Provider`、`Mode` 等字段；
3. 只有当历史回溯、多行编辑或滚动查看成为真实痛点时，再引入完整 TUI；
4. 新增任何视觉元素时，必须同时定义非终端纯文本表现。

## 8. M3.2 审批与运行反馈设计

M3.1 的 `write_file` 已经具备预览、确认、原子写入和 `.drift/changes` 记录。M3.2 只优化交互表现，不扩大写入权限。

### 8.1 写入审批面板

真实终端使用方向键选择，不再要求手动输入 `y`：

```text
WriteFile command

  F:\code\drift\tmp\hello.txt

  This command requires approval

❯ 1. Yes
  2. Yes, and don't ask again for this pattern
  3. No
```

选择完成后，面板消失，只保留一行结果和耗时。第二项只在当前 chat 进程内有效，不写入会话、审计或变更记录。

### 8.2 紧凑进度

读写工具统一使用“处理中 → 完成/失败”的短状态，显示实时耗时：

```text
● Write hello.txt ...
✓ Write hello.txt (11 bytes) · 0.2s
```

普通 TTY 不展开完整 diff 头；完整 diff 仍在 `.drift/changes`，`--trace` 保留详细事件流。非终端继续输出纯文本。

### 8.3 失败提示与边界

预检失败应同时满足两点：给用户明确的安全原因（如父目录不存在），给模型脱敏错误；模型不应为了解释失败而读取 Drift 自身的实现源码。M3.2 仍不自动创建目录，也不提供永久权限、完整 TUI、删除、命令执行或 Git 回滚。

### 8.4 运行中状态与模型兼容性

真实 TTY 的每个交互轮在无工具输出时显示单行旋转状态：

```text
⠋ Thinking...  (2s)
```

该行使用暗灰色，与工具开始/完成行、审批面板互斥；工具事件或模型文本开始输出时清除，当前轮结束时再次清除。重定向输出不写入 ANSI 或 spinner。

部分 OpenAI 兼容模型会在原生工具调用后返回 DSML/伪工具文本。Drift 不执行这类文本：工具调用已经发生过时，最多追加一次无工具纯文本请求；首轮直接返回伪工具文本，或重试后仍返回伪工具文本，均以明确错误结束。

### 8.5 固定底栏与多文件审批（M3.3）

#### 持续 TTY Chat（M3.3.1）

真实 TTY 只能有一个长期运行的 Bubble Tea 程序。它统一拥有聊天 transcript、输入框、底栏、`/resume` 选择器和写入审批层；Agent、工具与权限回调只发送事件，禁止直接写 stdout。这样用户消息、工具结果和 `Done` 都进入同一份可重绘 transcript，弹窗确认后从状态中移除，不会遗留在终端。

```text
viewport: 用户消息 / 工具结果 / 流式回答 / Done
──────────────────────────────────────────────
overlay: /resume 或审批（仅激活期间显示）
──────────────────────────────────────────────
❯ 输入框
──────────────────────────────────────────────
  Enter 发送 · Ctrl+C 取消                 <model>
```

- 一个用户回合只追加一个用户消息与一个 `Done`；
- 工具调用开始仅驱动 spinner，完成时才追加紧凑结果行；
- 工具调用采用可更新活动行：开始显示 `● Read README.md ...` / `● Write hello.txt ...`，完成后原地替换为 `✓ Read README.md · 8.2 KB · 0.4s`；
- 读取、搜索和写入的活动行使用同一套开始/完成结构；正常的创建前探测失败会移除活动行，不留下红色噪声；
- 创建前 `read_file` 未命中属于探测，不显示为红色失败；
- 用户提示符 `❯` 使用青色，助手标记 `●` 使用紫色，成功结果使用绿色，失败结果使用红色；正文保持浅灰色，底栏和分隔线使用暗灰色；
- 分隔线始终按当前终端宽度铺满，不使用固定短横线；模型名不得截断，空间不足时完整换到下一行；
- 输入框根据可见换行动态增高，底部第二条分隔线随输入下移，不能遮挡多行输入；
- 输入区紧跟当前 transcript：短回答不强行把输入推到终端最底部，内容超出窗口后才由 viewport 滚动；
- transcript 支持 `PageUp` / `PageDown`（以及鼠标滚轮）滚动；用户手动滚动后保持当前位置，新事件到达时才恢复跟随底部；
- `/resume` 等斜杠命令先进入 transcript，再打开选择器；切换后只显示目标会话内容，不保留旧选择器；
- 非 TTY 保留按行纯文本循环，避免破坏脚本调用。

输入、viewport、审批和 `/resume` 选择器由同一个长期运行的 Bubble Tea 编辑器负责；用户按 Enter 后不会切换到另一个终端输出通道。输入区默认紧跟最后一条消息，只有 transcript 溢出时才启用滚动区域。

当前 TTY 回合已采用终端原生滚动区域实现固定布局：

```text
聊天 transcript（内容不足时不填满窗口；超出时自动滚动到底部）
────────────────────────────────
❯ 当前输入
────────────────────────────────
  Enter 发送 · Ctrl+C 取消                 deepseek-v4-flash
```

- viewport 负责用户消息、助手回答、Thinking、工具进度和审批结果；
- 输入框、操作提示和模型名属于 transcript 后的输入区，不额外制造大块空白；
- 每轮输入读取终端窗口大小并计算 viewport 高度，内容超出时才滚动；
- 模型回合结束或取消时恢复滚动区域并清理底栏，下一轮输入重新绘制；
- 非 TTY（管道、重定向、测试输出）不写 ANSI 控制序列，保留纯文本行为。
- 审批面板显示在 viewport 的末端，选择完成后从活动内容中移除，只保留紧凑结果行；
- 工具调用开始行属于瞬时活动状态，不写入聊天历史；完成后只保留一条结果行。创建前的 `read_file` 未命中属于正常探测，不显示为红色错误；
- 非 TTY 继续使用纯文本按行协议，不输出 ANSI、备用屏幕或光标控制序列。

M3.3 的多文件写入不再为每个文件创建独立顶层视觉区块。一个用户回合使用一个 change set，面板按文件显示简短操作行；审批仍以文件为粒度，完整 diff 在本地 change set 中保存。

### 8.6 写入意图与审批显示

当用户明确要求创建、写入、修改或删除时，模型应优先调用对应原生工具，不应只返回示例代码或声称修改已经完成。只有工具成功返回后，界面才显示成功状态。

审批面板继续使用三态选择：

```text
WriteFile command

  tmp/hello.txt

  This command requires approval

❯ 1. Yes
  2. Yes, and don't ask again for this pattern
  3. No
```

当前版本的“pattern”仅限当前 chat 进程内、同一工具/操作/路径；M3.3 如扩大到目录或路径模式，必须在面板中显示实际匹配范围，且不能绕过 workspace 和受保护目录校验。
