# Drift 面板视觉设计

这份文档记录 Drift 终端交互的视觉约定、调整原因和后续面板设计方向。以后涉及输入提示、回答展示、状态面板、颜色、分隔线、缩进和耗时信息的调整，都先在这里记录，再同步到对应阶段文档。

## 1. 设计目标

Drift 的终端输出需要让用户一眼分清：

- 当前正在输入什么；
- 哪些内容是模型回答；
- 哪些内容是本地命令反馈；
- 当前会话和上下文处于什么状态；
- 哪些数字是估算值，哪些数字来自 Provider 的真实数据。

设计参考 FoxCode 的终端体验，但只采用标准输出、ANSI 颜色和简单布局，不在当前阶段引入完整 TUI 或行编辑器。

## 2. 当前交互样式

### 2.1 输入提示

真实终端使用青色提示符：

```text
────────────────────────
❯ 请输入问题
```

非终端输出不写入 ANSI 控制字符，使用普通的 `> ` 作为兼容提示符。

普通文本命令不会发送给模型：

```text
status  -> 如需查看状态，请输入 /status
clear   -> 如需清空上下文，请输入 /clear
compact -> 如需压缩上下文，请输入 /compact
```

### 2.2 助手回答

助手回答使用独立标记，并在回答结束时显示本轮耗时：

```text
● 这是 Drift 的回答内容。

Completed · 2.4s
```

- `●` 使用紫色或洋红色；
- 回答正文使用默认前景色；
- 完成耗时使用暗灰色；
- 非终端输出保留纯文本标记，不输出 ANSI 控制符。

## 3. `/status` 状态面板

正式命令为 `/status`，不再保留 `/stats` 兼容命令。

当前布局：

```text
Drift Status
────────────────────

  Session ID:  conv-c57d13e4056f99b83306b787
  Model:       deepseek-v4-flash
  Context:     100% remaining
               2.3 KB used / 1048.6 KB total
  Tokens:      17 in / 9 out
  Tools:       3 enabled
  Workspace:   F:\code\drift
```

### 3.1 对齐规则

- 所有字段统一缩进两个空格；
- 字段名使用固定宽度，值从同一列开始；
- `Context` 的第二行对齐到值列；
- 分隔线长度与面板标题或内容宽度保持协调；
- 状态面板不输出用户提示词、文件内容或 Provider 密钥。

### 3.2 颜色规则

| 元素 | 建议颜色 | 说明 |
| --- | --- | --- |
| `Drift Status` | 蓝色/青色 | 面板标题 |
| 字段名 | 暗灰色 | `Session ID`、`Model` 等标签 |
| 普通值 | 默认前景色 | 会话 ID、模型名、工具数量 |
| `Workspace` | 青色 | 强调当前工作目录 |
| `Tokens: unavailable` | 暗黄色/暗灰色 | 表示 Provider 尚未返回真实 usage |
| 分隔线 | 暗灰色 | 降低视觉干扰 |

### 3.3 字段边界

当前显示：

- `Session ID`：当前完整会话 ID；临时模式显示 `temporary (not saved)`；
- `Model`：当前配置的模型名；
- `Context`：Drift 根据消息结构计算的字节估算，使用十进制 KB；
- `Tokens`：显示 Provider 返回的真实输入/输出 token；未返回时显示 `unavailable`，混合状态追加 `(partial)`；
- `Tools`：已注册的只读工具数量；
- `Workspace`：当前 workspace 根目录。

暂不显示 `Memory`，因为当前项目没有独立长期记忆系统；会话快照不能直接等同于 Memory。

## 4. 当前已知限制

当前 chat 使用 `bufio.Scanner` 按行读取输入，因此只能控制提示符和输出布局，不能完整控制用户输入中的光标、上下历史、多行编辑和输入框重绘。

如果未来要完全复刻 FoxCode 的输入区域，需要单独引入终端行编辑或 TUI 层，处理：

- 原始终端模式；
- 光标移动；
- 上下历史；
- 多行输入；
- 输入区域重绘；
- Windows Terminal、Linux TTY 和重定向输出的兼容。

这不属于当前 M1.4 的轻量视觉优化范围。

## 5. 人工验收清单

在项目根目录运行：

```powershell
go run ./cmd/drift chat -w .
```

依次输入：

```text
/status
status
clear
compact
你好，介绍一下你自己
exit
```

检查：

1. `/status` 显示英文状态字段，并且字段值对齐；
2. Context 第二行与其他值列对齐；
3. `status`、`clear`、`compact` 只显示命令提示，不触发模型请求；
4. 普通回答前有助手标记，结束后有 `Completed · <耗时>`；
5. 真实终端能看到颜色和分隔线；
6. 将输出重定向到文件时，不出现 ANSI 控制字符；
7. `Tokens: unavailable` 不被误认为真实 Token 用量。

## 6. 后续调整计划

按优先级排列：

1. 完成 `/status` 字段颜色和对齐优化；
2. 根据实际使用频率决定是否增加 `Provider`、`Mode` 等字段；
3. 只有当行输入、历史回溯或多行编辑成为真实痛点时，再引入完整 TUI；
4. 新增任何视觉元素时，必须同时定义非终端纯文本表现。
