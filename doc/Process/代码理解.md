# Drift 代码理解与阅读流程

这份文档是阅读当前代码的入口。每次新增阶段或修改运行链路时，应同步更新本文件中的“当前能力”“调用流程”“边界”和“阅读入口”；阶段历史仍写入 `doc/m0.*.md`，当前验收范围以 `spec/current.md` 为准。

## 1. 当前项目是什么

Drift 是一个使用 Go 标准库编写的本地只读 Coding Agent Runtime。它接收用户提示，调用一个 OpenAI Compatible Chat Completions SSE Provider；模型可以在受限 workspace 内使用三个工具探索文件，最终把回答输出到终端。

当前能力：

- `-p` 发送一次提示；`-w` 选择分析目录或初始关注文件；
- 工具：`list_files`、`search_text`、`read_file`；
- 最多 4 次模型请求、6 次工具调用、512 KiB 累计工具结果；
- 分页读取、目录噪声过滤、二进制拒绝；
- JSONL 会话审计、密钥/路径脱敏、Provider 错误阶段；
- 不支持写文件、删除文件、Shell 命令或执行程序。

## 2. 先记住的总调用链

```text
PowerShell: drift -w <路径> -p <问题>
    |
    v
cmd/drift/main.go
    | 创建可被 Ctrl+C 取消的 context，并交给 app.Run
    v
internal/app/app.go
    | 读 .env / 环境变量 / flag，解析 workspace，创建 Provider 与 JSONL Writer
    v
internal/agent/agent.go
    | 组装消息、请求模型、执行工具、按预算循环
    +--> internal/llm/openai/client.go
    |      HTTP POST + SSE 解码 -> llm.Completion
    +--> internal/tool/registry.go
    |      list_files / search_text / read_file
    v
internal/session/jsonl.go
    | 只追加安全审计元数据到 .drift/sessions/run-*.jsonl
    v
stdout：最终回答；stderr：诊断错误
```

## 3. 推荐阅读顺序

不要从所有工具细节开始。按下列顺序，每读完一个文件再运行对应测试，最容易建立整体感。

| 顺序 | 文件 | 先看什么 | 对应测试 |
| --- | --- | --- | --- |
| 1 | `cmd/drift/main.go` | 程序入口、Ctrl+C、标准输入输出 | `go test ./cmd/drift` |
| 2 | `internal/app/app.go` | 参数、配置、Provider、Session、Agent 的装配 | `go test ./internal/app -v` |
| 3 | `internal/app/workspace.go` | `-w` 如何变成 Root 与 Focus | `go test ./internal/app -run Workspace -v` |
| 4 | `internal/agent/agent.go` | 多轮 Agent Loop、预算、事件 | `go test ./internal/agent -v` |
| 5 | `internal/tool/registry.go`、`tool.go` | 模型能看见哪些工具 | `go test ./internal/tool -run Registry -v` |
| 6 | `internal/tool/walk.go` | 相对路径、软链接、目录忽略 | `go test ./internal/tool -run Walk -v` |
| 7 | `internal/tool/list.go`、`search.go`、`read.go` | 三个只读工具和各自上限 | `go test ./internal/tool -v` |
| 8 | `internal/llm/client.go`、`internal/llm/openai/client.go` | Provider 无关接口、HTTP/SSE 适配 | `go test ./internal/llm/openai -v` |
| 9 | `internal/session/jsonl.go`、`session.go` | 审计事件、脱敏、JSONL 写入 | `go test ./internal/session -v` |

`cmd/drift` 目前没有独立测试并不影响阅读；实际 CLI 行为主要由 `internal/app` 测试覆盖。

## 4. 从一条命令跟到最终回答

以此命令为例：

```powershell
go run ./cmd/drift -w F:\code\foxcode -p "读取 README.md，并说明项目作用"
```

### 4.1 入口和应用编排

`main.go` 创建 `context`。用户按 Ctrl+C 时它会取消，`app.Run` 最终返回退出码 `130`。

`app.Run` 依次做这些事：

1. 从**启动命令所在目录**读取可选 `.env`；
2. 合并配置：`-model` / `-base-url` > 进程环境变量 > `.env` > 内置地址；API Key 只来自环境变量或 `.env`；
3. 调用 `resolveWorkspace` 解析 `-w`；
4. 创建 OpenAI Compatible Provider；
5. 在 workspace 的 `.drift/sessions/` 创建本次 JSONL；
6. 调用 Agent，并把事件先写 JSONL，再把最终文本写入 stdout。

### 4.2 `-w` 规则

```text
不传 -w         Root = 当前目录，Focus = 空
-w 某个目录      Root = 该目录，Focus = 空
-w 某个普通文件  Root = 文件父目录，Focus = 文件名
```

Focus 只写入首轮系统提示，例如“优先围绕 README.md 回答”；它不会自动读取文件，也不额外消耗请求预算。工具仍只能接收 Root 内的相对路径，例如 `{"path":"README.md"}`。

### 4.3 Agent Loop

`RunEventsWithRegistry` 是运行核心。第一轮请求会带系统约束和三个工具 schema；后续轮次携带已发生的 assistant/tool 消息。

```text
模型完成且没有 tool_calls
  -> 输出缓存的最终文本 -> run_finished

模型返回 tool_calls
  -> 校验工具名称
  -> 按原顺序逐个执行
  -> 把 tool result 追加到 messages
  -> 再请求模型
```

达到工具数或总读取量限制后，最后一次允许的模型请求会移除工具 schema，要求模型基于已经获得的信息作答。这样模型不会继续索取内容，运行也不会无限循环。

### 4.4 Provider 和 SSE

`openai.Client.Stream` 负责把内部的 `llm.Request` 转换成 `POST /chat/completions`。它不会把 API Key 或 Provider 响应正文写入错误。

`readStream` 逐行读取 SSE：空行代表一个事件结束；同一工具调用可能分成多个 delta，所以按 `index` 累积到完整的 `ToolCall`。收到 `[DONE]` 后才返回 `Completion`。

失败会带一个稳定阶段，例如 `provider_transport`、`provider_timeout`、`provider_http`、`provider_sse_invalid_json`。Agent 把它转换为 `error` 事件，Session 再持久化为 JSONL 的 `stage` 字段。

### 4.5 Session

每个事件独立写一行 UTF-8 JSONL，典型顺序：

```text
run_started
tool_call
tool_result
text_delta
run_finished
```

失败时是 `run_started -> error`。新版本 Session 不保存提示词、工具参数、工具结果正文或回答正文，只保存已知只读工具的安全相对路径、`<redacted>`、对应字节数和安全 `finish_reason`；密钥、Authorization、本地绝对路径和 dotenv 路径也会被脱敏或省略。Session 是审计记录，不是直接给 LLM 恢复的上下文。

PowerShell 查看时使用：

```powershell
Get-Content .drift\sessions\run-xxx.jsonl -Encoding utf8
```

JSONL 使用标准 UTF-8 且不写 BOM；旧 Windows PowerShell 若不显式指定编码，中文可能显示乱码。

查看摘要时可以使用：

```powershell
go run ./cmd/drift session list
go run ./cmd/drift session show .drift\sessions\run-xxx.jsonl
```

`session show` 只显示事件类型、工具名、安全相对路径、字节数、错误阶段和 `finish_reason`，不回显旧 JSONL 中的正文。

## 5. 三个工具与安全边界

| 工具 | 用途 | 主要上限 |
| --- | --- | --- |
| `list_files` | 递归列出普通文件 | 最多 200 条 |
| `search_text` | 在普通文本文件中进行字面量搜索 | 最多扫描 200 个文件、100 个匹配、32 KiB 输出 |
| `read_file` | 读取单文件或按行分页读取 | 单页/单文件最多 128 KiB |

所有工具共同遵守：

- 参数路径必须相对 Root；禁止绝对路径与 `..`；
- 禁止 `.env`、`.env.*`；
- 禁止符号链接、目录和特殊文件；
- `list_files`、`search_text` 会跳过 `.git`、`.drift`、`.codex`、`.claude`、`node_modules`、虚拟环境和缓存目录；
- `read_file` 发现 NUL 字节会拒绝二进制内容；
- 当前没有任何写入或命令执行工具。

分页中的 `offset` 从 0 开始，但输出给人看的行号从 1 开始：

```text
read_file: lines 21-40
...
read_file: more lines available; next offset: 40
```

## 6. 常见定位入口

| 现象 | 首先看哪里 |
| --- | --- |
| `.env` 没生效 | `internal/config/config.go`、启动目录是否正确 |
| `-w` 无效 | `internal/app/workspace.go` |
| 模型没调用工具 | `internal/agent/agent.go` 的 schema、模型返回的 `tool_calls` |
| 工具读取被拒绝 | `internal/tool/walk.go`、`read.go` 的路径和软链接检查 |
| 401 / 超时 / SSE 错误 | `internal/llm/openai/client.go`，再看 JSONL 的 `stage` |
| JSONL 没内容或有脱敏 | `internal/session/jsonl.go` |
| PowerShell 会话中文乱码 | `Get-Content ... -Encoding utf8` |

## 6.1 `--trace` 运行观察

需要理解一次运行是否经过了工具调用时，可以加上 `--trace`：

```powershell
go run ./cmd/drift --trace -p "分析 README.md"
```

`app.Run` 仍把每个 Agent Event 先交给 Session Writer；开启 trace 后，同一个事件再交给 `internal/app/trace.go`，只把安全摘要写到 stderr。`text_delta` 不复制正文，`tool_result` 只输出字节数，所以 trace 不会变成第二份文件内容日志。这个开关只观察 Runtime Event，不改变 Agent Loop 的请求、工具和预算。

## 7. 后续每次更新的最小流程

1. 先在 `spec/current.md` 写清当前阶段的范围、边界和验收标准；
2. 修改前先读受影响链路和对应测试；
3. 行为变更先写失败测试，再实现最小代码；
4. 只给跨层边界、限制原因、安全判断补中文注释，不逐行翻译 Go 语法；
5. 同步更新对应 `doc/m0.*.md` 和本文档；
6. 运行 `go test ./... -count=1`、`go vet ./...`、`go build ./cmd/drift`、`git diff --check`；
7. 提交前确认 `.env`、`.drift/` 和其他生成物没有进入暂存区。

## 8. 你现在可以怎样开始

建议先只走一遍“直接回答”路径：`main.go -> app.go -> agent.go -> openai/client.go`。理解后，再回到 `agent.go` 的 `tool_calls` 分支，并按工具注册表进入 `list/search/read`。每看完一层就运行上表中的单包测试；不需要一开始看完所有安全检查细节。
