# Drift 代码理解与阅读流程

这份文档是阅读当前代码的入口。每次新增阶段或修改运行链路时，应同步更新本文件中的“当前能力”“调用流程”“边界”和“阅读入口”；阶段历史写入对应阶段文档，当前验收范围以 `spec/current.md` 为准。

## 1. 当前项目是什么

Drift 是一个本地受控 Coding Agent Runtime。它接收用户提示，通过 OpenAI Compatible 或 Anthropic Messages Provider 调用模型；模型可以在受限 workspace 内探索文件，并在 `chat` 中经人工确认后写入文件。当前版本 M3.2：在交互 chat、完整会话保存与显式恢复的基础上，增加了日期分片存储、Skills、会话选择器、消息完整性保护、安全文件写入和 TTY 审批选择器。

当前能力：

- `-p` 发送一次提示；`-w` 选择分析目录或初始关注文件；
- `chat` 进入交互模式，空行忽略，`exit`/`/exit`/`quit` 或 EOF 退出；
- `chat` 中输入 `/clear` 清空当前 Runner 的内存上下文，不读取或删除 Session；
- 工具：`list_files`、`search_text`、`read_file`；
- 最多 4 次模型请求、6 次工具调用、512 KiB 累计工具结果；
- 分页读取、目录噪声过滤、二进制拒绝；
- JSONL 会话审计、密钥/路径脱敏、Provider 错误阶段；
- 1 MiB 对话上下文估算、`agent_context_limit` 和 `/clear`；
- M1.2 默认本地完整会话快照、`--resume`、`--no-session` 和 `conversation` 元数据命令；
- M1.3 支持会话标题、列表限制、删除预览和按时间清理；
- M1.4 支持 `/status` 查看上下文占用和 `/compact` 手动压缩上下文；
- M2.5 将运行时控制提示限定为瞬时 system context，完整快照不保存 `reasoning_content`，`session timeline` 只显示无正文的消息结构；
- M3.1 仅在 `chat` 注册 `write_file`；`-p` 保持只读。写入目标仍是 workspace 相对路径，修改过程记录在 `.drift/changes/YYYY/MM/DD/`，每次创建和覆盖都先确认。
- M3.2 使用方向键/数字键选择写入审批；当前 chat 可记忆同类允许操作，读写工具显示紧凑进度和耗时，失败时显示脱敏安全摘要。
- 不支持写文件、删除文件、Shell 命令或执行程序。

## 2. 先记住的总调用链

```text
PowerShell: drift -w <路径> -p <问题> 或 drift chat [--resume|--no-session] -w <路径>
    |
    v
cmd/drift/main.go
    | 创建可被 Ctrl+C 取消的 context，并交给 app.Run
    v
internal/app/app.go
    | 读 .env / 环境变量 / flag，解析 workspace，创建 Provider、完整快照与 JSONL Writer
    v
internal/agent/agent.go
    | 组装消息、请求模型、执行工具、按预算循环
    +--> internal/llm/openai/client.go
    |      HTTP POST + SSE 解码 -> llm.Completion
    +--> internal/tool/registry.go
    |      list_files / search_text / read_file
    v
internal/conversation/store.go
    | .drift/sessions/ 完整消息快照，供显式 --resume 恢复
    +--> internal/session/jsonl.go
           只追加安全审计元数据到 .drift/audits/run-*.jsonl
    v
stdout：最终回答；stderr：诊断错误
```

交互模式会在 `app.RunWithInput` 中识别 `chat`，先解析 `--resume`/`--no-session`，再装配 Provider、workspace、工具注册表和 Session Writer。默认创建或加载 `.drift/sessions/<id>.json`，Runner 从快照复制消息；每轮成功后再保存消息。`--no-session` 跳过完整快照但仍写审计。每次 Provider 请求前都会估算 system、消息和工具 schema 的 UTF-8 字节数，超过 1 MiB 时只结束当前输入轮次并等待 `/clear`。

## 3. 推荐阅读顺序

不要从所有工具细节开始。按下列顺序，每读完一个文件再运行对应测试，最容易建立整体感。

| 2 | `internal/app/app.go`、`internal/app/chat.go` | 参数、配置、Provider、Session、单次与交互模式装配 | `go test ./internal/app -v` |

| 4 | `internal/agent/agent.go` | 多轮 Agent Loop、预算、事件 | `go test ./internal/agent -v` |

| 6 | `internal/tool/walk.go` | 相对路径、软链接、目录忽略 | `go test ./internal/tool -run Walk -v` |
| 7 | `internal/tool/list.go`、`search.go`、`read.go` | 三个只读工具和各自上限 | `go test ./internal/tool -v` |

`cmd/drift` 目前没有独立测试并不影响阅读；实际 CLI 行为主要由 `internal/app` 测试覆盖。

## 4. 从一条命令跟到最终回答

以此命令为例：

```powershell
go run ./cmd/drift -w F:\code\foxcode -p "读取 README.md，并说明项目作用"
```

### 4.1 入口和应用编排

`main.go` 创建 `context`。用户按 Ctrl+C 时它会取消，`app.Run` 最终返回退出码 `130`。

`app.Run` 依次做这些事：

1. 从**启动命令所在目录**读取可选 `.env`；
2. 合并配置：`-model` / `-base-url` > 进程环境变量 > `.env` > 内置地址；API Key 只来自环境变量或 `.env`；
3. 调用 `resolveWorkspace` 解析 `-w`；
4. 创建 OpenAI Compatible Provider；
5. 在 workspace 的 `.drift/audits/` 创建本次 JSONL；
6. 调用 Agent，并把事件先写 JSONL，再把最终文本写入 stdout。

### 4.2 `-w` 规则

```text
不传 -w         Root = 当前目录，Focus = 空
-w 某个目录      Root = 该目录，Focus = 空
-w 某个普通文件  Root = 文件父目录，Focus = 文件名
```

Focus 只写入首轮系统提示，例如“优先围绕 README.md 回答”；它不会自动读取文件，也不额外消耗请求预算。工具仍只能接收 Root 内的相对路径，例如 `{"path":"README.md"}`。

### 4.3 Agent Loop

`RunEventsWithRegistry` 是运行核心。第一轮请求会带系统约束和三个工具 schema；后续轮次携带已发生的 assistant/tool 消息。

```text
模型完成且没有 tool_calls
  -> 输出缓存的最终文本 -> run_finished

模型返回 tool_calls
  -> 校验工具名称
  -> 按原顺序逐个执行
  -> 把 tool result 追加到 messages
  -> 再请求模型
```

达到工具数或总读取量限制后，最后一次允许的模型请求会移除工具 schema，要求模型基于已经获得的信息作答。这样模型不会继续索取内容，运行也不会无限循环。

### 4.4 Provider 和 SSE

`openai.Client.Stream` 负责把内部的 `llm.Request` 转换成 `POST /chat/completions`。它不会把 API Key 或 Provider 响应正文写入错误。

`readStream` 逐行读取 SSE：空行代表一个事件结束；同一工具调用可能分成多个 delta，所以按 `index` 累积到完整的 `ToolCall`。收到 `[DONE]` 后才返回 `Completion`。

失败会带一个稳定阶段，例如 `provider_transport`、`provider_timeout`、`provider_http`、`provider_sse_invalid_json`。Agent 把它转换为 `error` 事件，Session 再持久化为 JSONL 的 `stage` 字段。

### 4.5 Session

每个事件独立写一行 UTF-8 JSONL，典型顺序：

```text
run_started
tool_call
tool_result
text_delta
run_finished
```

失败时是 `run_started -> error`。新版本 Session 不保存提示词、工具参数、工具结果正文或回答正文，只保存已知只读工具的安全相对路径、`<redacted>`、对应字节数和安全 `finish_reason`；密钥、Authorization、本地绝对路径和 dotenv 路径也会被脱敏或省略。Session 是审计记录，不是直接给 LLM 恢复的上下文。

PowerShell 查看时使用：

```powershell
Get-Content .drift\sessions\run-xxx.jsonl -Encoding utf8
```

JSONL 使用标准 UTF-8 且不写 BOM；旧 Windows PowerShell 若不显式指定编码，中文可能显示乱码。

查看摘要时可以使用：

```powershell
go run ./cmd/drift audit list
go run ./cmd/drift audit show .drift\audits\run-xxx.jsonl
```

`audit show` 只显示事件类型、工具名、安全相对路径、字节数、错误阶段和 `finish_reason`，不回显旧 JSONL 中的正文。

## 4.6 交互模式如何复用和清理上下文

```powershell
go run ./cmd/drift chat -w .
```

`app.RunWithInput` 只在进入 chat 时创建一个 `agent.Runner`。`internal/app/chat.go` 用 `bufio.Scanner` 逐行读取：空行继续等待，退出命令结束循环，普通输入交给 `Runner.RunEvents`。Runner 首轮追加系统指令和工具 schema，后续轮次直接使用内存中的 user、assistant、tool 消息；持久模式每轮成功后把消息写回完整快照，再把事件写入脱敏 JSONL 审计。预算耗尽或 DSML 终答重试所需的控制文字只临时附加到当次 system context，绝不能用 `Role: "user"` 追加到 Runner 消息，否则恢复后模型会误以为那是用户输入。

输入 `/clear` 时，chat 直接调用 `Runner.ResetContext()`，不请求 Provider、不追加 `run_started`，只保留 workspace、focus、Provider 和工具注册表。上下文超限时会写入 `agent_context_limit` 错误事件，当前轮次结束但 chat 继续运行，用户可以输入 `/clear` 后继续。

`session` 和 `audit` 是两套不同职责：`session` 管理可恢复的完整快照，`audit` 只查看脱敏事件，审计不会被 LLM 读取，也不会作为恢复来源。需要恢复时只能通过 `--resume` 读取当前 workspace 的 `.drift/sessions/` 快照；`--no-session` 则只保留当前进程内存和脱敏审计。

如果 Provider 返回 `finish_reason=stop` 但没有文本，Runner 会生成 `agent_empty_response` 错误事件并结束本轮，而不是直接显示下一个 `> `。这类情况应先查看 `--trace` 和 Session 的 `error.stage`，区分 Provider 空响应与本地输出问题。

## 4.7 M1.2 完整会话恢复

```text
chat 启动
  -> --resume 指定 ID：Store.Load；未指定 ID：Store.Latest
  -> Runner.NewRunnerWithMessages 深拷贝消息
  -> 成功 RunEvents 后 Store.Save
  -> /clear：先保存空快照，成功后 Runner.ResetContext
```

完整快照可能包含提示词、回答和工具结果，不是脱敏数据；`session show` 只输出元数据，不能用来查看正文，`session timeline <id>` 只输出角色、工具调用和字节数，适合检查消息结构。快照不包含 API Key、Provider URL、模型名或 workspace 绝对路径，也不会保存 Provider `reasoning_content`。`session` 命令在 `.env` 加载和 Provider 创建之前分发，因此不需要 API Key。

## 4.8 M1.3 会话生命周期管理

`internal/conversation/store.go` 递归扫描 UTC 日期目录，不引入额外索引。`title` 由用户通过 `session rename` 或 chat 内 `/rename` 设置；`list --limit` 只截取已按更新时间排序的元数据。`prune --before` 默认只预览，只有显式 `--yes` 才会逐个重新加载并删除仍早于阈值的快照，因此不会因旧列表竞态误删新会话。

这些命令在应用入口的 `session` 分支中、加载 `.env` 和创建 Provider 之前执行。它们只操作 `.drift/sessions/`，不会删除 `.drift/audits/` 审计，也不会把完整正文输出到终端；`audit` 分支只读取 `.drift/audits/`，不触碰完整会话。

## 4.9 M1.4 上下文统计与压缩

`/stats` 直接读取 `Runner.ContextBytes()` 和 `Runner.Messages()`，因此不会产生模型请求。`/compact` 先把当前消息复制到一个无工具 Provider 请求中；只有摘要非空、格式合法且持久快照保存成功后，才替换 Runner 消息。失败路径恢复原消息并继续 chat。

压缩事件通过统一 Runtime Event 进入 Session/Trace，但只保存 `before_bytes`、`after_bytes`、消息数、保留数和错误 `stage`。摘要正文不会写入审计或 trace；完整快照仍可能保存压缩后的摘要，因此不能把压缩理解为敏感信息擦除。

## 5. 三个工具与安全边界

| 工具 | 用途 | 主要上限 |
| --- | --- | --- |
| `list_files` | 递归列出普通文件 | 最多 200 条 |
| `search_text` | 在普通文本文件中进行字面量搜索 | 最多扫描 200 个文件、100 个匹配、32 KiB 输出 |
| `read_file` | 读取单文件或按行分页读取 | 单页/单文件最多 128 KiB |

所有工具共同遵守：

- 参数路径必须相对 Root；禁止绝对路径与 `..`；
- 禁止 `.env`、`.env.*`；
- 禁止符号链接、目录和特殊文件；
- `list_files`、`search_text` 会跳过 `.git`、`.drift`、`.codex`、`.claude`、`node_modules`、虚拟环境和缓存目录；
- `read_file` 发现 NUL 字节会拒绝二进制内容；
- 当前没有任何写入或命令执行工具。

分页中的 `offset` 从 0 开始，但输出给人看的行号从 1 开始：

```text
read_file: lines 21-40
...
read_file: more lines available; next offset: 40
```

## 6. 常见定位入口

| 现象 | 首先看哪里 |
| --- | --- |
| `.env` 没生效 | `internal/config/config.go`、启动目录是否正确 |
| `-w` 无效 | `internal/app/workspace.go` |
| 模型没调用工具 | `internal/agent/agent.go` 的 schema、模型返回的 `tool_calls` |
| 工具读取被拒绝 | `internal/tool/walk.go`、`read.go` 的路径和软链接检查 |
| 401 / 超时 / SSE 错误 | `internal/llm/openai/client.go`，再看 JSONL 的 `stage` |
| 第二轮直接出现下一个提示符 | 先查看 Session 是否为 `agent_empty_response`，再用 `--trace` 复现 |
| JSONL 没内容或有脱敏 | `internal/session/jsonl.go` |
| PowerShell 会话中文乱码 | `Get-Content ... -Encoding utf8` |

## 6.1 `--trace` 运行观察

需要理解一次运行是否经过了工具调用时，可以加上 `--trace`：

```powershell
go run ./cmd/drift --trace -p "分析 README.md"
```

`app.Run` 仍把每个 Agent Event 先交给 Session Writer；开启 trace 后，同一个事件再交给 `internal/app/trace.go`，只把安全摘要写到 stderr。`text_delta` 不复制正文，`tool_result` 只输出字节数，所以 trace 不会变成第二份文件内容日志。这个开关只观察 Runtime Event，不改变 Agent Loop 的请求、工具和预算。

## 6.2 `.drift` 存储布局（M2.2/M2.3/M2.4）

当前目录职责统一为：

```text
.drift/
├── sessions/
│   └── YYYY/MM/DD/  # 完整会话快照，chat --resume 与 /resume 使用
├── audits/
│   └── YYYY/MM/DD/  # 脱敏 JSONL 审计，audit list/show 使用
└── skills/     # workspace Skill
```

M2.4 起，新文件按 UTC 年/月/日分片，并采用“前缀-时间-ID”命名：`sessions/YYYY/MM/DD/session-<timestamp>-<id>.json` 与 `audits/YYYY/MM/DD/run-<timestamp>-<audit-id>.jsonl`。不再读取旧的平铺路径，也不在启动时自动迁移或删除旧文件；旧数据由用户显式清理。因此审计永远不是会话恢复来源。

chat 内 `/resume` 只从 `conversation.Store.List/Load` 获取完整快照；无参数时进入本地选择器，按标题、首条用户消息和 ID 过滤，Esc 取消。目标快照成功加载后才替换 Runner 和 persistence，失败时保留原会话。`/new` 在持久模式下先创建新的空快照，再清空 Runner；`--no-session` 只清空内存，不写完整会话。

## 7. 后续每次更新的最小流程

1. 先在 `spec/current.md` 写清当前阶段的范围、边界和验收标准；
2. 修改前先读受影响链路和对应测试；
3. 行为变更先写失败测试，再实现最小代码；
4. 只给跨层边界、限制原因、安全判断补中文注释，不逐行翻译 Go 语法；
5. 同步更新对应 `doc/m0.*.md` 和本文档；
6. 运行 `go test ./... -count=1`、`go vet ./...`、`go build ./cmd/drift`、`git diff --check`；
7. 提交前确认 `.env`、`.drift/` 和其他生成物没有进入暂存区。

## 8. 你现在可以怎样开始

建议先只走一遍“直接回答”路径：`main.go -> app.go -> agent.go -> openai/client.go`。理解后，再回到 `agent.go` 的 `tool_calls` 分支，并按工具注册表进入 `list/search/read`。每看完一层就运行上表中的单包测试；不需要一开始看完所有安全检查细节。
