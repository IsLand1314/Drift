# M1.9：Anthropic Messages Provider

## 目标

在不改变 Agent、工具、会话和终端交互接口的前提下，增加可选 Anthropic Messages SSE Provider，验证 Provider 差异只停留在 `internal/llm/<provider>`。

## 配置

```powershell
$env:ANTHROPIC_API_KEY = "本机密钥"
$env:ANTHROPIC_BASE_URL = "https://api.anthropic.com/v1"
$env:ANTHROPIC_MODEL = "你的模型"
go run ./cmd/drift -provider anthropic -p "介绍 README.md"
```

也可把同名配置放在本地 `.env`；`.env` 已被 Git 忽略，不能提交真实密钥。

## 调用流程

`cmd/drift` 解析 `-provider` → `app` 读取对应配置并创建 Provider → `internal/llm/anthropic` 将通用消息和工具 schema 编码为 `/messages` → 解析 Anthropic SSE → 归一化为 `llm.Event` → Agent 串行执行只读工具 → 下一轮发送 `tool_result` → chat、会话和审计继续沿用现有实现。

## 人工验收

1. 先运行 `go test ./... -count=1`，确认本地模拟测试通过。
2. 配置真实 Anthropic Key 和 Model，运行上面的文本命令，确认 stdout 只有最终回答。
3. 提问“读取 README.md 并说明作用”，确认模型发起 `read_file` 后能完成第二轮回答。
4. 运行 `go run ./cmd/drift chat -provider anthropic -w .`，在 `/status` 中确认 Model、Tokens、Tools 和 Workspace 正常显示。
5. 删除 `ANTHROPIC_API_KEY` 后再次运行，确认在 HTTP 请求前报配置错误。
6. 检查 `.drift/sessions/*.jsonl` 和 `--trace` 输出，确认没有 API Key、`x-api-key`、原始响应、完整请求体或绝对路径。

## 有意不做

本阶段不加入重试、Thinking、服务器工具、MCP、写文件、命令执行、自动 Provider 降级或 Anthropic 专有字段进入 Agent。需要这些能力时另立阶段和验收标准。
