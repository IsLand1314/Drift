# M1.0：交互式只读对话

M1.0 在已有 M0.9 只读 Agent Loop 上增加一个最小交互入口：`drift chat`。同一进程内的多次输入共享 Agent 的内存消息上下文，因此用户可以先让模型读取文件，再追问文件或项目含义。

## 使用方式

```powershell
go run ./cmd/drift chat -w .
```

进入后逐行输入问题。空行会被忽略，输入 `exit`、`/exit` 或 `quit` 退出；EOF（Ctrl+Z 后回车或管道结束）也会正常退出。

```text
> 读取 README.md
（模型回答）
> 这个项目的作用是什么？
（模型基于同一进程上下文继续回答）
> exit
```

`-w`、`--trace`、`-model` 和 `-base-url` 与单次模式一致。`-p` 与 `chat` 互斥。

## 调用流程

```text
CLI 识别 chat
  -> 一次性加载 .env、Provider、workspace、只读工具注册表和 JSONL Writer
  -> 创建 agent.Runner（消息只保存在当前进程内存）
  -> 读取一行输入
  -> Runner.RunEvents：请求模型、执行只读工具、继续请求直到最终回答
  -> 输出回答，并把安全 Runtime Event 追加到同一个审计文件
  -> 下一行复用同一个 Runner
```

首个问题会带系统约束和工具 schema；后续问题携带此前的 user、assistant、tool 消息。每一轮仍使用 M0.4 的单轮预算：最多 4 次模型请求、6 次工具调用、512 KiB 累计工具结果和 128 KiB 单文件读取。

## 明确边界

- 对话上下文只存在内存，进程退出后丢失；不会从 `.drift/sessions/*.jsonl` 恢复，也不会把审计内容发送给模型。
- Session JSONL 仍只保存脱敏审计摘要：事件类型、工具名、安全相对路径、字节数、错误阶段和结束原因，不保存提示词、文件内容或回答正文。
- 仍只有 `list_files`、`search_text`、`read_file` 三个只读工具；不支持写文件、删除文件、编辑文件、Shell 或命令执行。
- 任一轮发生 Provider、工具、输出或取消错误时，本次命令结束；不会静默创建新的 Runner 继续执行。
- Provider 以 `finish_reason=stop` 结束但没有文本时，Agent 返回 `agent_empty_response` 错误并写入审计；不会把空回答当成成功，也不会直接跳到下一个提示符。

## 验收

1. `go run ./cmd/drift chat -w .` 能连续回答两个问题，第二个问题能引用第一个问题已获得的上下文。
2. `exit`、`/exit`、`quit` 和 EOF 不发起 Provider 请求并返回 0；空行不会产生请求。
3. `--trace` 仍只向 stderr 输出安全摘要，stdout 只输出回答。
4. `.drift/sessions/` 只出现一个本次 chat 的 JSONL 文件，内容不含原始问题、回答、文件内容、API Key 或绝对路径。
5. Provider 返回空最终内容时，终端显示明确错误，Session 的 `error.stage` 为 `agent_empty_response`。
6. `go test ./... -count=1`、`go vet ./...`、`go build ./cmd/drift` 和 `git diff --check` 通过。
