# M3.1 安全文件写入

M3.1 是 Drift 从只读 Runtime 进入受控写入的第一步。

## 写入边界

- `drift -p` 仍是单次只读模式，不注册 `write_file`。
- `drift chat` 注册 `write_file`，创建或覆盖文件前必须人工确认。
- 目标路径是 workspace 内的相对路径；不允许绝对路径、`..`、符号链接逃逸或 `.git`、`.drift`、`.codex-temp`、`.worktrees` 目录。
- 目标父目录必须预先存在，M3.1 不自动创建目录。

## 本地修改记录

项目文件写入 workspace 的请求路径；本次操作的 `manifest.json`、`diff.patch` 和临时内容写入：

```text
.drift/changes/YYYY/MM/DD/change-<timestamp>-<id>/
```

`changes` 只用于本地修改过程记录，不是会话恢复来源，也不是脱敏审计来源。过程记录可能包含项目敏感内容，不应上传。

## 当前非目标

M3.1 暂不支持 `edit_file`、删除文件、命令执行、测试运行、OS 沙箱和 Git 回滚；这些属于后续 M3 阶段。
