# M0.4：受限多轮只读探索 Agent 设计

状态：设计阶段。本文记录 M0.4 的目标、边界和验收标准；实现完成后，`spec/current.md` 仍是当前交付范围的唯一事实来源。

## 1. 目标

M0.3 已经打通了“首轮决定是否读取文件、第二轮生成答案”的两轮闭环。M0.4 将它扩展为受限多轮只读探索，让模型能够根据前一步结果继续选择下一步，而不是在首轮一次性猜出所有路径。

典型流程：

```text
list_files -> search_text -> read_file -> read_file -> 最终回答
```

本阶段仍然是只读 Runtime，不进入写文件、编辑文件或执行命令阶段。

## 2. 明确不做

- 不允许写文件、删除文件、编辑文件、shell 或 exec；
- 不允许会话恢复、上下文压缩、TUI、Web、MCP 或第二个 Provider；
- 不开放任意文件系统路径；用户指定 workspace 的能力另立阶段；
- 不并发执行工具；工具调用保持串行，便于顺序审计和限制总量；
- 不取消现有 workspace、符号链接、dotenv、文件大小和脱敏边界。

## 3. 推荐方案

保留现有 `llm.Client`、`tool.Registry`、Runtime Event 和 JSONL Writer，只替换 Agent 的固定两轮控制流，并增加两个内建只读工具：

```text
internal/app
  创建 Provider、Registry、Session Writer
        |
internal/agent
  请求模型 -> 校验工具调用 -> 串行执行工具 -> 追加上下文 -> 再请求模型
        |
internal/tool
  list_files / search_text / read_file
        |
internal/session
  每个事件追加一行并即时 Flush
```

Agent 每一轮都可以得到工具 schema；当模型以 `stop` 结束且没有工具调用时结束运行。只要模型返回工具调用，就执行工具并进入下一轮，直到成功回答或触达上限。

## 4. 运行上限

上限是 Runtime 的稳定性边界，不是工具实现细节：

- 单次运行最多 4 次模型请求；
- 单次运行最多 6 次工具调用；
- `read_file` 单文件最多 128 KiB；
- 单次运行所有工具成功结果进入上下文的总量最多 512 KiB；
- `list_files` 返回条目数和 `search_text` 返回匹配数、字节数必须有固定上限；
- 触达工具调用数或上下文总量上限时，不再执行新的工具调用；如果仍有模型请求预算，则追加受控限制结果并用“不带工具 schema”的最后一轮请求生成说明，否则直接以受控错误结束。

M0.4 的上限值集中定义，测试直接覆盖边界；不做无限循环或隐式超时重试。

## 5. 工具契约

### `list_files`

输入为 workspace 内的相对目录，空值表示 workspace 根目录。输出为排序后的相对文件路径，不递归跟随符号链接，不返回 `.env`、`.env.*` 和特殊文件。目录深度、条目数和单条路径长度都要限制，结果超过上限时返回“结果已截断”的可读标记。

### `search_text`

输入为关键词和可选的相对目录；只搜索普通文本文件，不读取 dotenv，不跟随符号链接。输出包含相对路径、行号和有限长度的匹配片段；搜索文件数、匹配数和返回字节数都受限。搜索错误必须脱敏，不把绝对路径交给模型。

### `read_file`

沿用 M0.3 行为：相对路径、禁止 `..`、符号链接、目录、特殊文件、dotenv 和超大文件。M0.4 不扩大其权限范围。

所有工具继续通过 `tool.Registry` 注册，Agent 不通过工具名称写死分派逻辑。

## 6. Agent Loop 行为

1. 发出 `run_started`；
2. 使用当前上下文和 Registry schema 请求 Provider；
3. 聚合完整 tool call，先校验本轮调用数量和工具名称；
4. 按模型返回顺序串行执行工具；
5. 每个调用发出 `tool_call`，完成后发出 `tool_result`；
6. 将脱敏后的工具错误或受限结果加入下一轮上下文；
7. 累加请求数、调用数和上下文字节数，满足限制后停止扩展；
8. `stop` 且没有工具调用时，流式发出最终 `text_delta`，再发出 `run_finished`；
9. Provider、工具、取消或 sink 错误发出 `error`，不再继续请求。

首轮工具前导文本不输出到 stdout；所有最终回答文本仍由 CLI 流式输出。JSONL 中的 `text_delta` 继续使用 `<redacted>` 占位符，避免跨分片重建敏感信息。

## 7. 失败与退出行为

- 工具参数无效、未知工具、工具数量超限：记录受控错误，不执行越界调用；
- 请求次数、工具次数或上下文总量达到上限：记录受控错误；有剩余请求预算时只允许一次无工具 schema 的最终说明请求；
- Provider 返回第二次工具调用时不再视为协议错误，只要尚未达到上限就继续下一轮；
- Provider 流协议错误、JSONL 写入失败和取消保持现有退出码约定；
- 任何错误文本都不能包含 API Key、Authorization、dotenv 内容或本地绝对路径。

## 8. 事件与审计

不新增事件类型。多轮运行只是重复以下已有事件序列：

```text
run_started
tool_call
tool_result
tool_call
tool_result
text_delta
run_finished
```

每个事件立即追加并 Flush。审计文件仍位于 `.drift/sessions/run-*.jsonl`，不支持加载和恢复。

## 9. 测试与验收

至少覆盖以下关键路径：

- 直接回答仍只请求一次模型；
- `list_files -> read_file -> 最终回答` 多轮闭环；
- `search_text -> read_file -> 最终回答` 多轮闭环；
- 4 次模型请求和 6 次工具调用上限；
- 工具结果总量和单文件大小上限；
- 未知工具、错误参数、工具失败和取消；
- list/search 的路径遍历、符号链接、dotenv、目录和特殊文件边界；
- 多轮 JSONL 事件顺序、即时落盘和脱敏；
- stdout 只包含最终回答，不包含工具过程；
- `go test ./... -count=1`、`go vet ./...`、`go build ./cmd/drift` 和 `git diff --check` 通过。

## 10. 后续阶段

M0.4 完成后，Drift 能在用户指定的 workspace 内受限地浏览、搜索和读取代码。之后再评估可控写入：计划展示、Diff 预览、用户确认、回滚和权限策略必须一起设计，不直接把 `write_file` 接到当前循环。
