# M1.4：手动上下文压缩

M1.4 为 `drift chat` 增加 `/status` 和 `/compact`，解决长对话达到 1 MiB 上限后只能完全 `/clear` 的问题，并提供轻量终端交互反馈。

## 使用方式

```powershell
go run ./cmd/drift chat -w .
```

在 chat 中输入：

```text
/status
/compact
```

`/status` 示例：

```text
Drift Status
────────────────────────
Session ID: conv-xxxxxxxxxxxxxxxxxxxxxxxx
Model: deepseek-v4-flash
Context: 99% remaining
         13.5 KB used / 1048.6 KB total
Tokens: unavailable
Tools: 3 enabled
Workspace: F:\code\drift
```

这里的上下文大小是 Drift 对将要发送给 Provider 的消息结构所作的字节估算，不是 Provider 返回的 token 用量。`--no-session` 模式显示 `Session ID: temporary (not saved)`。当前 Provider 未返回 usage 时，Token 显示 `unavailable`。

`/compact` 会让当前 Provider 生成摘要，保留摘要和最近一组完整消息，然后继续对话。成功时显示：

```text
上下文已压缩：保留最近 N 条消息
```

## 与 `/clear` 的区别

| 命令 | Provider 请求 | 结果 |
| --- | --- | --- |
| `/status` | 否 | 只显示运行状态，不修改上下文 |
| `/compact` | 是，且不带工具 | 用摘要和最近消息替换旧上下文 |
| `/clear` | 否 | 清空当前上下文；持久模式保存空快照 |
| `clear` | 否 | 只提示使用 `/clear`，不改变上下文 |
| `status` / `compact` | 否 | 分别提示使用 `/status` / `/compact`，不交给模型 |

真实终端中的输入区域使用分隔线和青色 `❯`，助手回答使用紫色圆点开头，完成后显示本轮耗时；状态面板标题和分隔线使用终端颜色；非终端输出保持纯文本。该轻量展示不改变模型请求、会话内容或审计格式。

## 安全与失败行为

- `/compact` 的请求仍可能包含当前提示词、回答和文件内容；摘要不是安全擦除证明。
- 压缩请求不携带 `list_files`、`search_text` 或 `read_file` 工具，不会执行文件操作。
- Provider 超时、空回答、DSML 伪工具文本、取消或快照保存失败时，原上下文保持不变，chat 继续运行。
- `.drift/sessions/` 只记录压缩前后字节数、消息数、保留数和错误 stage，不记录摘要正文。
- 持久模式压缩成功后会更新 `.drift/conversations/<id>.json`；下次 `--resume` 恢复压缩后的上下文。

## 人工验收

1. 在 chat 输入 `/status`，确认没有 Provider 请求，显示英文状态字段、剩余百分比和 KB 估算。
2. 输入 `/compact`，确认显示压缩成功，并在下一轮继续回答。
3. 分别输入普通 `status`、`compact`，确认只显示斜杠命令提示，Provider 请求数不增加；输入 `/stats` 不再触发本地状态面板。
4. 完成一次普通提问，确认终端显示分隔线、助手标记和 `Completed · <耗时>`；将输出重定向到文件时不含 ANSI 控制符。
5. 使用模拟 Provider 或断网使压缩失败，确认旧上下文仍可继续使用。
6. 退出后执行 `chat --resume <id> -w .`，确认恢复摘要后的会话。
7. 查看最新 Session JSONL，确认没有摘要正文、提示词或文件内容。

## 当前不做

本阶段不实现真实 Provider Token usage、Memory 子系统、完整 TUI/行编辑器、自动压缩、后台压缩、摘要树、fork、`/undo`、摘要编辑、加密、云同步、跨 workspace 恢复和正文搜索。
