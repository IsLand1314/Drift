# M1.4：手动上下文压缩

M1.4 为 `drift chat` 增加 `/stats` 和 `/compact`，解决长对话达到 1 MiB 上限后只能完全 `/clear` 的问题。

## 使用方式

```powershell
go run ./cmd/drift chat -w .
```

在 chat 中输入：

```text
/stats
/compact
```

`/stats` 示例：

```text
上下文：13868 / 1048576 bytes
消息：7
剩余：1034708 bytes
```

`/compact` 会让当前 Provider 生成摘要，保留摘要和最近一组完整消息，然后继续对话。成功时显示：

```text
上下文已压缩：保留最近 N 条消息
```

## 与 `/clear` 的区别

| 命令 | Provider 请求 | 结果 |
| --- | --- | --- |
| `/stats` | 否 | 只显示计数，不修改上下文 |
| `/compact` | 是，且不带工具 | 用摘要和最近消息替换旧上下文 |
| `/clear` | 否 | 清空当前上下文；持久模式保存空快照 |
| `clear` | 否 | 只提示使用 `/clear`，不改变上下文 |

## 安全与失败行为

- `/compact` 的请求仍可能包含当前提示词、回答和文件内容；摘要不是安全擦除证明。
- 压缩请求不携带 `list_files`、`search_text` 或 `read_file` 工具，不会执行文件操作。
- Provider 超时、空回答、DSML 伪工具文本、取消或快照保存失败时，原上下文保持不变，chat 继续运行。
- `.drift/sessions/` 只记录压缩前后字节数、消息数、保留数和错误 stage，不记录摘要正文。
- 持久模式压缩成功后会更新 `.drift/conversations/<id>.json`；下次 `--resume` 恢复压缩后的上下文。

## 人工验收

1. 在 chat 输入 `/stats`，确认没有 Provider 请求，只显示 bytes 和消息数量。
2. 输入 `/compact`，确认显示压缩成功，并在下一轮继续回答。
3. 使用模拟 Provider 或断网使压缩失败，确认旧上下文仍可继续使用。
4. 退出后执行 `chat --resume <id> -w .`，确认恢复摘要后的会话。
5. 查看最新 Session JSONL，确认没有摘要正文、提示词或文件内容。

## 当前不做

本阶段不实现自动压缩、后台压缩、摘要树、fork、`/undo`、摘要编辑、加密、云同步、跨 workspace 恢复和正文搜索。
