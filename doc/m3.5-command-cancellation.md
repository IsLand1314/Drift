# M3.5 命令取消与进程树终止

M3.5 在 M3.4 `run_command` 的基础上，补齐命令取消后的进程生命周期管理。

## 行为

- 活动轮次按 Ctrl+C：只取消当前 Agent 轮和正在运行的命令，chat 保持运行。
- 空闲输入框按 Ctrl+C：保持原有行为，退出 chat。
- 取消、超时、非零退出分别返回 `cancelled`、`timeout`、`failed`，都不能被模型或 UI 当成成功。
- Windows 优先使用 Job Object；如果当前宿主禁止嵌套 Job Object，则回退到 `taskkill /T /F`。
- Unix 使用独立 process group，先发 `SIGTERM`，再在有限等待后发 `SIGKILL`。
- TUI 显示 `当前轮已取消；会话仍可继续`，不直接显示原始 `context canceled`。

## 不改变的边界

- `ask / allow / deny` 仍是 M3.4 的当前 chat 精确匹配语义。
- `-p`、`audit` 和 session 管理仍不暴露 `run_command`。
- 审计和完整会话不保存命令输出正文或回答正文。

## 自动化验证

```powershell
go test ./internal/tool -run 'Command.*Cancel|Command.*ProcessTree' -count=1

```

## TTY 人工验证

启动 `drift chat` 后，让模型执行一个持续命令，在命令运行期间按 Ctrl+C：应看到取消提示、回到输入框，并能继续发送下一条消息。空闲输入框再次按 Ctrl+C 时，进程应以 130 退出。

本阶段不把人工 TTY 的显示截图写入仓库；验收记录只保留结果摘要，不保存 API Key、回答正文或完整命令输出。
