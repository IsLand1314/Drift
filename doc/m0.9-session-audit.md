# M0.9：安全 Session 审计与查看器

M0.9 明确 `.drift/sessions/*.jsonl` 的职责：它是本地安全审计记录，不是完整聊天记录，也不会自动作为上下文发送给 LLM。

## 命令

列出当前 workspace 的会话文件：

```powershell
go run ./cmd/drift session list
```

查看某个会话的安全摘要：

```powershell
go run ./cmd/drift session show .drift\sessions\run-123.jsonl
```

输出类似：

```text
2026-09-30T10:00:00Z run_started text_bytes=24
2026-09-30T10:00:01Z tool_call tool=read_file path=README.md argument_bytes=18
2026-09-30T10:00:01Z tool_result tool=read_file result_bytes=4557
2026-09-30T10:00:03Z run_finished
```

## M0.9.1：记录安全的相对路径

为了审计“模型请求读取了哪个目标”，已知只读工具的调用事件可以额外保存 `path`：

- 仅处理 `read_file`、`list_files`、`search_text` 的工具调用参数；
- 统一使用 `/` 分隔符；
- 只保存相对路径；绝对路径、`..`、`.env`/`.env.*` 和控制字符路径直接省略；
- 完整 `arguments` 仍保存为 `<redacted>`，不会因为记录路径而恢复原始参数；
- 工具结果事件不重复保存路径，避免增加审计噪声。

因此 `session show` 可以显示 `path=README.md`，但仍不会显示文件内容、提示词、原始参数或模型回答。

## M0.9.2：记录安全的结束原因

运行结束或异常结束时，审计事件可以保存 Provider 返回的 `finish_reason`：

- 正常完成通常显示 `finish_reason=stop`；
- 模型达到输出上限时可能显示 `finish_reason=length`；
- Provider 连接、SSE 或工具错误仍通过 `stage` 区分；
- 该字段只记录稳定的原因枚举，不保存 Provider 响应正文。

例如：

```text
2026-09-30T10:00:03Z run_finished finish_reason=stop
```

这样可以区分“模型正常结束”和“模型因为长度或协议异常而提前结束”。

## 保存内容

新运行的 JSONL 只保存：

- 事件类型和时间；
- 工具名；
- 已知只读工具调用经过校验的相对 `path`；
- `text_bytes`、`argument_bytes`、`result_bytes`；
- 错误信息的脱敏版本和 `stage`；
- `<redacted>` 占位符。

它不保存用户提示词、原始工具参数、工具结果正文或模型回答正文。旧 JSONL 可能仍有历史正文，但 `session show` 只读取其结构和元数据，不回显旧正文。

## 为什么不直接给 LLM 读取

本地审计记录和模型上下文是两个安全边界：本地文件可能包含源码、配置、个人信息或未被规则识别的密钥。自动把整个历史记录重新发送给 Provider，会在用户没有明确意识的情况下扩大数据外发范围。

因此 M0.9 不提供 `--resume`。未来如果实现会话恢复，需要单独的上下文格式、再次脱敏、明确用户授权和发送前提示。
