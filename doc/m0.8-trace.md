# M0.8：Trace 运行可观测性

M0.8 在现有 Runtime Event 之上增加可选的 `--trace`。它用于理解一次运行经过了哪些关键步骤，不改变 Agent Loop、Provider、工具边界或 JSONL 事实记录。

## 使用

```powershell
go run ./cmd/drift --trace -w F:\code\foxcode -p "分析 README.md"
```

stdout 仍然只输出最终回答；trace 写入 stderr。典型摘要如下：

```text
[drift] run_started
[drift] tool_call list_files
[drift] tool_result list_files bytes=842
[drift] tool_call read_file
[drift] tool_result read_file bytes=4096
[drift] run_finished
```

如果 Provider 失败，trace 会记录阶段：

```text
[drift] run_started
[drift] error stage=provider_transport
```

## 安全边界

Trace 只输出事件摘要，不输出：

- 用户提示词或模型回答正文；
- 工具原始 arguments、文件内容或完整工具结果；
- API Key、Authorization、Provider 响应正文；
- workspace 绝对路径。

工具结果显示的是 Go 字节长度，不是内容。完整审计仍在 `.drift/sessions/*.jsonl` 中保存，并沿用 Session 的脱敏规则。trace 写入 stderr 失败时不会让 Agent 运行失败。

## 验收

```powershell
go test ./... -count=1
go vet ./...
go build ./cmd/drift
git diff --check
```

人工验证时确认：

1. `--trace` 开启后 stdout 只有最终回答；
2. stderr 包含 `run_started` / `run_finished`，工具路径包含工具名和字节数；
3. 失败运行包含 `error stage=...`；
4. 输出中没有回答正文、密钥、文件内容或绝对路径；
5. 不传 `--trace` 时现有命令输出不变。
