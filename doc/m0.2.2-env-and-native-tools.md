# M0.2.2：环境配置与原生工具兼容性

## 目标与范围

M0.2.2 在 M0.2.1 的受限多文件只读 Agent Loop 上补齐本地配置说明，并记录一次真实的 Provider 兼容性边界：Drift 只接受 OpenAI Compatible Chat Completions SSE 中的原生 `tool_calls`，不把模型自行生成的 DSML/XML 片段当作工具调用。

## 本地配置

`.env` 是可选的当前工作目录配置文件。PowerShell 可从无密钥模板创建它：

```powershell
Copy-Item .env.example .env
```

填写 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_MODEL`。`.env` 已加入 `.gitignore`，只应保留在本机；不要把密钥提交到仓库、写进 README、命令行、截图或诊断日志。`.env.example` 可提交，且 API Key 为空。为避免密钥进入模型上下文，`read_file` 会拒绝读取 `.env` 和所有 `.env.*` 文件（包括 `.env.example`）。

配置来源的优先级如下：

1. `-model` 和 `-base-url` 命令行参数覆盖模型和地址。
2. 同名进程环境变量覆盖 `.env`。
3. `.env` 覆盖内置默认值；缺少 `.env` 不会报错。
4. API Key 没有命令行参数，只从 `OPENAI_API_KEY` 的进程环境或 `.env` 读取。

例如：

```powershell
$env:OPENAI_API_KEY = "本机密钥"
$env:OPENAI_BASE_URL = "https://api.deepseek.com"
$env:OPENAI_MODEL = "deepseek-v4-flash"
go run ./cmd/drift -p "解释 README.md 的项目作用"
```

若没有 Key 或模型，Drift 在发出请求前返回配置错误。测试使用本地模拟 Provider；没有 `OPENAI_API_KEY` 时，不能据此宣称完成真实 DeepSeek 请求。

## 原生工具与 DSML 边界

首轮请求只提供一个原生 `read_file` function schema，并附带系统指令说明 Drift 是只读的，`run_command`、shell 和 exec 不可用。模型若返回标准 OpenAI `tool_calls`，Drift 最多按顺序读取四个文件，再将结果放进同一个第二轮请求。一次命令最多两次模型请求；每个文件最多 128 KiB，成功读取合计最多 512 KiB。没有写文件、删除文件、改名、执行命令或运行程序的能力。

`<｜｜DSML｜｜ calls>`（以及 `<|DSML|>`）是模型生成的文本标记，不是 OpenAI 响应里的原生 `tool_calls` 事件。它通常表示 Provider 或模型尝试使用自己的伪工具协议；当前实现只在“首轮没有原生 `tool_calls`、`finish_reason` 为 `stop`”时检查缓存的首轮文本。在这个精确范围内，Drift 会将标记报告为不兼容伪工具调用，丢弃首轮文本，不写入 stdout，也不会执行其中的命令。伴随原生工具调用的 DSML 文本以及第二轮文本不由此守卫拒绝。该行为不会新增 `run_command`，也不会放宽只读边界。

## 验证命令

在 worktree 根目录执行：

```powershell
go test ./... -count=1
go vet ./...
go build ./cmd/drift
git diff --check
```

还应确认：

- `go test` 的本地 SSE/httptest 覆盖首轮原生 `read_file` schema、DSML 拒绝、配置优先级和最多两次请求；
- 测试或 CLI 输出中没有 API Key；
- `git status --short` 中真实 `.env` 不会出现（模板 `.env.example` 应保持受跟踪状态）；
- 若没有 `OPENAI_API_KEY`，只做上述本地验证，不运行或宣称真实 DeepSeek 联调。
