# M3.6：工作区权限策略持久化设计

## 目标

让用户在当前工作区内选择“允许此类操作”后，可以在后续 chat 进程中复用同一条精确授权；默认安全行为保持为 `ask`，授权范围不得扩大。

## 范围

M3.6 只持久化审批界面第二项 `Yes, and don't ask again for this pattern`。第一项 `Yes` 只对当前操作有效，第三项 `No` 不写入策略。已有的当前进程内 `permissionMemory` 继续保留，并在持久化策略之前检查。

本阶段不做：用户级全局授权、通配符/正则模式、命令白名单、跨工作区授权、永久 `allow all`、后台任务、权限继承或自动批准只读工具。

## 授权匹配

授权键由以下字段组成，字段必须全部相等才算命中：

- `tool`：工具名，例如 `write_file`、`edit_file`、`delete_file`、`run_command`；
- `operation`：工具预览生成的操作类型；
- 文件工具使用规范化的工作区相对 `path`；
- 命令工具使用规范化的相对 `cwd` 与完整命令字符串 `command`。

不使用 glob、前缀或模糊匹配。路径仍经过现有 workspace、隐藏内部目录、符号链接和特殊文件校验；权限命中不能绕过这些安全检查。

## 存储位置与格式

文件位置固定为当前 workspace 的 `.drift/permissions.json`。文件和父目录沿用现有 `.drift` 权限策略：目录 `0700`，文件 `0600`。

格式使用版本化 JSON，便于拒绝未知结构而不误放行：

```json
{
  "version": 1,
  "rules": [
    {
      "tool": "write_file",
      "operation": "create_file",
      "path": "tmp/hello.txt",
      "created_at": "2026-10-02T10:00:00Z"
    },
    {
      "tool": "run_command",
      "operation": "run_command",
      "command": "go test ./...",
      "cwd": ".",
      "created_at": "2026-10-02T10:01:00Z"
    }
  ]
}
```

字段规则：

- `version` 必须为 `1`；未知版本按损坏配置处理；
- `rules` 缺失、重复或字段类型错误时，整个文件安全降级为空策略；
- 文件不存在等同于没有持久化授权；
- 加载、解析、权限检查或保存失败只能回退到 `ask`，不能自动放行；
- 保存采用同目录临时文件、`0600` 权限和原子替换，不直接覆盖旧文件。

## 生命周期与数据流

1. chat 启动时，以 workspace 根目录加载 `permissions.json`；加载失败只显示简短警告并继续使用 `ask`。
2. 工具预览完成后，权限回调先检查当前进程内存，再检查持久化规则。
3. 命中规则时直接返回 `Allow=true`，原因使用稳定值 `persistent_pattern_approved`。
4. 用户选择第一项时返回 `user_approved`，不修改策略文件。
5. 用户选择第二项时先执行当前操作；操作成功后才追加规则并原子保存。操作失败不得新增授权。
6. 用户选择第三项或取消时不修改策略文件。
7. 退出 chat 不删除策略；策略只绑定当前 workspace。

策略写入只接受已经通过现有工具预览和安全校验的请求，禁止模型或用户输入直接构造任意规则。

## 管理命令

新增两个 chat 内命令：

- `/permissions`：显示当前 workspace 的授权数量和脱敏摘要（工具、操作、相对路径或命令/cwd），不显示文件内容；
- `/permissions clear`：清空当前 workspace 的全部持久化授权，原子保存空规则文件；失败时保留旧文件并显示错误。

命令不会显示或修改其他 workspace 的策略，也不影响当前进程未落盘的临时授权。

## 审计与会话

审计允许记录工具名、操作类型、授权来源（`session`、`persistent`、`user`、`deny`）和结果；不记录完整命令输出、回答正文、文件内容或密钥。完整会话快照不保存策略正文，只保存现有消息和用量数据。

## 错误处理与安全降级

- 损坏 JSON、未知版本、重复规则、非对象规则项：视为空策略并继续 `ask`；
- `.drift` 或权限文件不可写：第一项仍可执行，第二项执行后提示“本次已允许，但持久化失败”，不伪装为已保存；
- 策略命中但当前请求未通过工具安全校验：拒绝执行并保留 `ask` 边界；
- 并发保存采用进程内互斥，避免同一 chat 的两个审批覆盖彼此规则；不承诺跨进程并发合并。

## 验收标准

| ID         | 场景                       | 通过标准                                                     |
| ---------- | -------------------------- | ------------------------------------------------------------ |
| AC-M36-001 | 新建 workspace，无权限文件 | 写入/编辑/删除/命令默认每次出现审批                          |
| AC-M36-002 | 当前 chat 选择第一项       | 当前操作成功；退出并重进后仍出现审批                         |
| AC-M36-003 | 当前 chat 选择第二项       | 当前操作成功；退出并重进后同一工具、同一操作、同一路径或命令/cwd 不再审批 |
| AC-M36-004 | 精确匹配边界               | 改路径、工具、操作、命令或 cwd 任一字段后仍出现审批          |
| AC-M36-005 | 拒绝与取消                 | 不修改目标，不新增规则                                       |
| AC-M36-006 | 操作失败后选择第二项       | 不新增规则；下一次仍出现审批                                 |
| AC-M36-007 | 损坏/未知版本策略          | chat 可启动，所有写入默认 ask，不自动放行                    |
| AC-M36-008 | `/permissions`             | 只显示脱敏规则摘要和数量，不泄露文件内容或密钥               |
| AC-M36-009 | `/permissions clear`       | 规则清空；下一次匹配操作重新 ask；保存失败时旧规则保留       |
| AC-M36-010 | 全量回归                   | `go test ./...`、`go vet ./...`、`go build ./cmd/drift`、`git diff --check` 全部通过 |

## 取舍

首版选择工作区级、精确匹配和安全降级，牺牲跨项目便利性换取授权边界可解释、可删除、可审计。暂不引入用户级配置、规则编辑器或复杂模式语言；只有在真实使用中出现重复授权成本后再单独设计。

## 已实现

- `.drift/permissions.json`，版本化 JSON，工作区级隔离；
- `write_file`、`edit_file`、`delete_file`、`run_command` 使用工具 + 操作 + 路径/命令 + cwd 精确匹配；
- 只有选择“允许此类操作”且工具执行成功后才写入；
- 写入失败、拒绝、取消和损坏配置均不自动放行；
- `/permissions` 和 `/permissions clear`；
- 策略文件使用 `0600`，同目录临时文件原子替换；
- 现有 workspace、符号链接、隐藏目录、特殊文件和命令边界不被策略绕过。
