# M2.5：消息完整性与会话时间线

## 目标

避免 Drift 自己生成的运行时控制提示被模型误认为用户输入，并提供不泄露正文的会话结构检查方式。

## 已交付

- 预算耗尽后的无工具终答提示，以及 DSML 伪工具文本的重试提示，只追加到当次模型请求的 system context。
- 上述控制提示不会进入 `Runner.Messages()`，因此新保存的完整会话不会出现伪造的 `role=user` 记录。
- 完整会话 JSON 不再写入或恢复 Provider `reasoning_content`；运行中的必要字段仍留在内存，快照恢复只保留角色、内容和原生工具调用所需信息。
- 新增 `drift session timeline <id>`：仅输出消息序号、角色、工具名、工具调用 ID 和正文大小，不输出任何消息正文。

## 保持不变的边界

- `.drift/sessions/` 继续使用 JSON 快照进行恢复；不因为“消息行数更多”改为 JSONL。
- `.drift/audits/` 继续使用脱敏 JSONL 记录运行事件；它不是恢复来源。
- 不新增逐消息时间戳。此项等会话格式和交互体验收敛后另行设计。
- 历史快照不自动清理或重写；其中已有的旧控制文本需要由用户按需保留、清理或创建新会话隔离。

## 验证

```powershell
go test ./internal/agent ./internal/conversation ./internal/app -run 'Test(RunToolBudgetUsesToolFreeFinalRequest|RunExactToolBudgetAddsLimitInstruction|RunEnforcesAggregateReadBudget|StoreDoesNotPersistReasoningContent|ConversationTimelineShowsStructureWithoutBodies)$' -count=1
go test ./... -count=1
go vet ./...
go build -o .codex-temp\drift-m25.exe ./cmd/drift
```

人工检查新建会话时，可运行：

```powershell
go run ./cmd/drift session timeline conv-<id>
```

输出中不应出现提示词、回答或工具结果正文；只应有 `user`、`assistant`、`tool`、工具调用信息和 `bytes`。
