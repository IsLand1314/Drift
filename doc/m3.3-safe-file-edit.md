# M3.3 安全文件编辑与变更集合

M3.3 完成 Drift 的受控文件修改能力。它扩展 M3.1 的 `write_file`，增加目录创建、精确编辑和文件删除，但暂不执行 shell、测试或其他命令。

## 范围

- 只在 `drift chat` 注册写入工具；`-p` 继续只读。
- `write_file` 支持 workspace 内缺失父目录的安全创建，并可在同一用户回合连续创建多个文件。
- 新增 `edit_file`：按唯一匹配的旧文本替换新文本；匹配 0 次或超过 1 次都拒绝，不修改文件。
- 新增 `delete_file`：只删除 workspace 内的普通文件，目录、符号链接、受保护目录和不存在目标都拒绝。
- 所有变更先预检，再由用户审批；拒绝、取消或预检失败不产生项目文件副作用。
- 继续使用当前 chat 进程内的权限记忆；默认按工具、操作和路径精确匹配。目录/通配模式只有在显示实际匹配范围并完成测试后才允许加入。

## 路径与内容边界

- 所有路径必须是 workspace 相对路径；拒绝绝对路径、`..`、符号链接逃逸、`.git`、`.drift`、`.codex-temp` 和 `.worktrees`。
- 写入和编辑只接受 UTF-8 文本；二进制目标拒绝编辑或覆盖。
- 单文件最大 128 KiB；单轮累计修改文件数和新增字节数必须有明确上限，超过后停止继续调用修改工具。
- 自动创建目录只创建缺失的普通目录，并在 workspace 根边界内逐级检查；不跟随已有符号链接。

## 变更集合

当前 M3.1 每次 `write_file` 都创建一个独立 `change-*` 目录。M3.3 改为每个用户回合创建一个 change set：

```text
.drift/changes/YYYY/MM/DD/change-<timestamp>-<id>/
├── manifest.json
├── diff.patch
└── work/
    ├── path/to/created-or-edited-file
    └── deleted-file.before
```

`manifest.json` 包含回合级 ID、时间、文件操作列表、审批结果、字节统计和错误摘要；`diff.patch` 聚合本回合所有文件的 diff；`work/` 保存创建/编辑后的内容以及删除前的内容。正文只保存在本地 changes，不进入 session 或 audit。

审批仍以文件为粒度，因此一个回合可以出现多个独立批准或拒绝结果，但它们写入同一个 change set。若进程中途取消，已批准并落盘的文件不自动回滚；manifest 必须标记 `partial`，避免伪装成全成功。

## 工具接口

### `write_file`

保留 `path` 与 `content` 参数；预检结果额外列出将创建的父目录。成功结果只报告相对路径、操作类型和字节数。

### `edit_file`

```json
{
  "path": "src/main.go",
  "old_text": "old unique text",
  "new_text": "new text"
}
```

要求 `old_text` 非空且在目标文本中恰好出现一次。工具必须在提交前重新校验目标内容，目标自上次读取后发生变化时拒绝，防止覆盖外部修改。

### `delete_file`

```json
{"path":"tmp/hello.txt"}
```

删除预览显示相对路径、原始字节数和可恢复副本位置；用户拒绝或取消时目标保持不变。

## 明确非目标

- 不新增 `run_command`、测试运行、OS 沙箱、永久权限配置或 Git 回滚。
- 不把 `audit` 命令扩展为变更管理命令。
- 不将 change set 设计成会话恢复格式，也不改写现有 session JSON 快照。

## 验收重点

1. 创建多级目录和多个文件，逐文件审批，change set 只生成一个顶层目录。
2. 编辑唯一匹配成功；0 匹配和多匹配均无副作用。
3. 删除前审批；拒绝、取消、符号链接和受保护路径均安全失败。
4. 中途取消后 manifest 标记部分完成，已批准文件状态准确。
5. `-p` 不暴露任何写入工具；chat 仍只允许 workspace 内受控变更。
6. 全量测试、vet、构建、diff 检查和真实 TTY 验证通过。
