# M0.3：Runtime 基础——事件流、JSONL 会话与工具注册

## 目标

在保留当前只读 `read_file` 行为的前提下，把 Drift 从“CLI 直接驱动 Agent”整理成可审计、可扩展的 Runtime 内核。

本阶段只处理三件事：

1. Agent 输出统一 Runtime Event；
2. 每次运行追加一份 JSONL 会话审计记录；
3. 工具通过 Registry 注册和查找，Agent 不再硬编码工具分派。

## 明确不做

- 不增加 `write_file`、`edit_file`、`run_command` 或 shell；
- 不增加 TUI、Web、MCP 或第二个 Provider；
- 不实现会话恢复和上下文压缩；
- 不改变当前两次 Provider 请求、最多四次 `read_file` 和只读 workspace 限制；
- 不把 API Key、`.env` 内容或本地绝对路径写入会话。

## 目标调用链

```
text
app
 ├─ 加载配置
 ├─ 创建 OpenAI Compatible Client
 ├─ 创建 Tool Registry（当前只有 read_file）
 ├─ 创建 Session JSONL Writer
 └─ 启动 agent.RunEvents
       ├─ 发出 Runtime Event
       ├─ Registry 查找并执行 read_file
       └─ 继续第二轮模型请求
              ├─ ui/print 消费文本事件
              └─ session 追加审计事件
```

## Runtime Event 契约

事件定义在 `internal/agent/event.go`，不暴露 Provider 的 SSE 分片类型。

```
go
type EventType string

const (
    EventRunStarted  EventType = "run_started"
    EventTextDelta   EventType = "text_delta"
    EventToolCall    EventType = "tool_call"
    EventToolResult  EventType = "tool_result"
    EventError       EventType = "error"
    EventRunFinished EventType = "run_finished"
)

type Event struct {
    Type       EventType
    Text       string
    ToolCallID string
    ToolName   string
    Arguments  string
    Result     string
    Error      string
}

type EventSink func(Event) error
```

约束：

- `run_started` 只携带用户提示词；
- `text_delta` 只携带最终可见文本，首轮工具前导文本仍然缓存；
- `tool_call` 在完整调用聚合后按顺序发出；
- `tool_result` 在本地工具返回后发出，失败结果使用脱敏文本；
- Agent 只对内部错误做最小脱敏；写入 JSONL 前由会话 Writer 统一清理 API Key、请求头、凭据和绝对路径；
- `run_finished` 只表示 Agent 正常结束，不携带敏感上下文。

保留一个 `Run` 兼容包装器，把 `text_delta` 转交给现有 `emitText`，因此当前 CLI 调用方式不变；新增 `RunEvents` 供 app 和会话记录使用。

## Tool Registry 契约

工具定义在 `internal/tool/tool.go` 和 `internal/tool/registry.go`。Registry 只负责注册、校验名称、导出 schema 和查找，不负责权限策略。

```
go
type Tool interface {
    Name() string
    Definition() llm.ToolDefinition
    Execute(ctx context.Context, root string, rawArguments string) (string, error)
}

type Registry interface {
    Definitions() []llm.ToolDefinition
    Lookup(name string) (Tool, bool)
}
```

`read_file` 作为第一个内建工具适配到该接口；原有 `tool.Read` 保留为兼容函数并委托给同一实现。Registry 不允许重复名称，Agent 遇到未注册工具时立即返回现有的受控错误。

## JSONL 会话格式

会话写入 `.drift/sessions/<run-id>.jsonl`。目录和文件由 Runtime 创建，`.drift/` 已在 `.gitignore` 中忽略。

每行是一个独立 JSON 对象：

```json
{"version":1,"type":"run_started","time":"2026-09-19T00:00:00Z","text":"解释 README.md"}
{"version":1,"type":"tool_call","time":"2026-09-19T00:00:01Z","tool_call_id":"call-1","tool":"read_file","arguments":"{\"path\":\"README.md\"}"}
{"version":1,"type":"tool_result","time":"2026-09-19T00:00:01Z","tool_call_id":"call-1","result":"..."}
{"version":1,"type":"text_delta","time":"2026-09-19T00:00:02Z","text":"<redacted>"}
{"version":1,"type":"run_finished","time":"2026-09-19T00:00:02Z"}
```

JSONL Writer 要求：

- 每次 Append 写完整一行并 Flush；
- `text_delta` 只记录 `<redacted>` 占位符，避免跨流式分片重建凭据或本地路径；CLI stdout 仍输出完整最终文本；
- 单行写入失败立即返回错误；
- 时间由 Writer 统一生成，使用 UTC；
- 不把 Provider 原始请求、Authorization header、API Key 或绝对路径写入文件；
- 当前阶段只负责审计，不负责加载、恢复或压缩会话。

## 验收标准

1. 直接回答仍只发起一次 Provider 请求，stdout 仍只有最终文本；
2. `read_file` 路径仍最多两次 Provider 请求、最多四个调用、单文件 128 KiB、总量 512 KiB；
3. 同一运行按顺序产生 `run_started`、工具调用/结果、文本和结束事件；
4. `.drift/sessions/*.jsonl` 可被标准 JSON 解码器逐行读取；
5. Provider 错误、工具错误和取消都不会写入密钥或绝对路径；
6. Tool Registry 可以用 fake tool 测试，不需要改 Agent Loop；
7. `go test ./...`、`go vet ./...`、`go build ./cmd/drift` 和 `git diff --check` 通过。

## 后续边界

M0.4 才考虑 `list_files`、`search_text` 等安全只读工具。权限模型稳定后，M1 再考虑 `write_file`、`edit_file` 和 `run_command`。会话恢复、TUI 和上下文压缩不属于本阶段。
