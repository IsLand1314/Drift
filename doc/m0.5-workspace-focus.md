# M0.5：显式 Workspace 与 Focus 文件设计

状态：设计已确认，尚未实现。当前可运行版本仍是 M0.4；当前范围与验收标准仍以 `spec/current.md` 为准。

## 1. 目标

M0.4 的 workspace 固定为启动命令所在的当前目录。M0.5 允许用户用 `-w` 显式选择要分析的目录或文件，同时保持三个只读工具只能使用 workspace 内相对路径的边界。

这解决“从任意位置启动 Drift，分析另一个项目或单个文件”的需求，但不把磁盘任意绝对路径开放给模型。

## 2. CLI 契约

```powershell
drift -w F:\code\foxcode -p "分析这个项目"
drift -w .\README.md -p "解释这个文件"
drift -p "分析当前目录"
```

| 输入 | workspace | focus |
| --- | --- | --- |
| 不传 `-w` | 启动命令时的当前目录 | 空 |
| `-w <目录>` | 该目录 | 空 |
| `-w <普通文件>` | 该文件的父目录 | 相对于 workspace 的文件路径 |

例如 `-w .\README.md` 在 `F:\code\drift` 下执行时，得到：

```text
workspace = F:\code\drift
focus     = README.md
```

`focus` 统一使用斜杠分隔的相对路径，例如 `docs/overview.md`。

## 3. 安全模型

### 3.1 选择 workspace

1. 将 `-w` 按启动命令时的当前目录解析为绝对、清理后的路径；
2. 目标必须存在，且只能是实际目录或普通文件；
3. 拒绝目标本身为符号链接、特殊文件或无法规范化的路径；
4. 目录目标规范化后即为 workspace；文件目标的规范父目录为 workspace；
5. 文件目标还必须通过现有的 dotenv 规则，`.env` 与 `.env.*` 不能成为 focus；
6. 任一失败在模型请求前报告参数错误，退出码为 2。

M0.5 不允许通过 `-w` 选择多个根目录，也不引入 FoxCode 的临时目录、Memory 目录或 Worktree 目录白名单。

### 3.2 工具路径不变

选定 workspace 后，`list_files`、`search_text`、`read_file` 的 `path` 仍必须是相对路径：

```json
{"path":"README.md"}
```

以下形式继续拒绝：

```json
{"path":"F:\\code\\foxcode\\README.md"}
{"path":"../outside.txt"}
```

现有 workspace 内的 `..`、符号链接、dotenv、目录和特殊文件保护继续复用；M0.5 不为绝对工具路径开例外。

### 3.3 配置和审计位置

- `-w` 只选择分析对象，不改变 Drift 配置来源；`.env` 仍从启动命令时的当前目录加载，避免把目标项目的业务 `.env` 误当作 Drift 配置；
- 会话审计写到选定 workspace 的 `.drift/sessions/`；文件目标时写到其父目录；
- 目标项目中的 `.env` 始终不向模型暴露。

## 4. Focus 的行为

focus 是模型的初始方向，不是一次隐式工具调用。

首轮系统提示在现有只读指令后追加受控说明：

```text
用户指定的初始关注目标是 README.md。
请优先围绕该文件回答；必要时使用 read_file 读取。
```

规则：

- 不自动调用 `read_file`；
- 不增加模型请求次数、工具调用次数或上下文读取量；
- 模型仍可直接回答，或自行选择 `read_file`、`list_files`、`search_text`；
- 路径按安全转义后的相对形式注入，不能由文件名改变只读系统边界；
- 不传 `-w` 或 `-w` 指向目录时，不追加 focus 说明。

## 5. 实现边界

```text
cmd/drift
  -> app 解析 -w，并调用 workspace resolver
  -> workspace resolver 产出 { Root, Focus }
  -> app 用 Root 创建 Session Writer，并把 Root/Focus 交给 Agent
  -> agent 仅在首轮系统提示中加入 Focus
  -> tool 继续以 Root 打开 workspace，拒绝绝对 tool path
```

新增 `internal/app/workspace.go` 作为小型 workspace resolver。它只负责 CLI 目标到 `Root + Focus` 的转换；不承载工具权限、写入确认或 Git 逻辑。

Agent 不需要知道 `-w` 的原始绝对路径，只接收已验证的 root 与相对 focus。这样 Provider 请求、工具结果和 JSONL 仍不会包含本地绝对路径。

## 6. M0.5 实施顺序

1. 为 workspace resolver 写目录、普通文件、相对路径、绝对路径、缺失路径、符号链接、dotenv focus 的失败测试；
2. 增加 `-w` flag，并让 app 使用 resolver 返回的 root 创建会话和 Agent；
3. 在首轮系统提示中按 focus 条件加入提示；不改变后续轮的工具 schema 与消息上下文；
4. 更新本地 SSE 集成测试，验证文件 focus 只影响首轮提示，模型工具参数仍是相对路径；
5. 更新 M0.5 当前范围、README 与阶段文档，并跑完整验证。

## 7. 验收标准

- `drift -w <目录> -p ...` 的工具访问与会话审计都落在该目录；
- `drift -w <文件> -p ...` 的 workspace 是父目录，首轮提示含相对 focus，且没有自动读取；
- 不传 `-w` 的 M0.4 行为保持不变；
- 模型传入绝对工具路径、`..`、符号链接和 dotenv 路径仍被拒绝；
- 无效 `-w` 在任何 Provider 请求前以退出码 2 失败，错误文本不泄露不必要的绝对路径；
- JSONL、stdout、工具调用预算和 M0.4 多轮行为保持兼容；
- `go test ./... -count=1`、`go vet ./...`、`go build ./cmd/drift`、`git diff --check` 通过。

## 8. M0.5 之后

M0.6 再处理大文件分页读取和面向 discovery 工具的默认忽略目录（如 `.git`、`node_modules`、`.venv`）。默认忽略只影响列举与搜索，不应阻止用户明确读取 workspace 内的普通文件。

写入、编辑、Shell、Git Worktree、多根目录和人工权限确认不属于 M0.5；它们需要独立的 policy 设计与确认交互。
