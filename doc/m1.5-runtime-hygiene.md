# M1.5：运行时卫生与边界对齐

M1.5 修复只读 Runtime 的两项低成本债务，并让架构文档与实际代码一致。

## 当前范围

- Discovery 遍历跳过 `.worktrees` 和 `.codex-temp`，避免旧 worktree、构建缓存和临时文件进入模型上下文。
- DSML/伪工具格式守卫覆盖所有“没有原生 tool call 且以 stop 结束”的模型最终文本，不只检查每轮首个请求。
- `doc/architecture.md` 明确当前 M1.x 只有 `list_files`、`search_text`、`read_file` 三个只读工具，不继承 write/edit/exec/policy 的旧草案承诺。

## 明确不做

- 不增加写文件、删除文件、Shell 或命令执行；
- 不引入权限模式、Project Trust、Worktree 隔离或第二个 Provider；
- 不伪造 Provider Token usage；真实 usage 留待后续 Provider 能力。

## 人工验收

1. 在 workspace 内创建 `.worktrees/demo/hidden.txt` 和 `.codex-temp/build.txt`，让 Agent 执行 `list_files`，确认两个目录不会出现在结果中。
2. 使用能先返回原生工具调用、再返回 `<｜｜DSML｜｜ calls>` 的模拟 Provider，确认运行失败并报告伪工具格式，不输出伪工具文本。
3. 检查 `doc/architecture.md`，确认当前工具、只读边界和后续候选与实现一致。
4. 执行 `go test ./... -count=1`、`go vet ./...`、`go build ./cmd/drift` 和 `git diff --check`。

先运行：

```
go run ./cmd/drift chat -w .
```

输入：

```
/status
```

检查：

- 显示 `Session ID`；
- 显示当前 Model；
- 显示 Context 剩余百分比；
- 显示 KB；
- 显示 Tools 数量；
- 显示 Workspace；
- `Tokens: unavailable` 不应被误认为真实 Token；
- 所有字段和值能看出颜色区别；
- 字段值从同一列开始；
- Context 第二行和其他值列对齐。

再检查普通命令：

```
status
compact
```

应该只显示：

```
如需查看状态，请输入 /status
如需压缩上下文，请输入 /compact
```

不能触发模型请求。

检查非终端输出：

```
go run ./cmd/drift chat -w . > status.txt
Select-String "Drift Status|Session ID|Model|Workspace" status.txt
```

重定向文件中不应出现 ANSI 控制字符。
