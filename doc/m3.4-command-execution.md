# M3.4 受控命令执行

M3.4 在 `chat` 中增加受控的 `run_command`，用于运行用户明确要求的命令和测试；`-p` 仍然只读，`audit` 仍然只查看脱敏审计。

## 范围

- `run_command` 只在 `drift chat` 注册，默认工作目录是当前 workspace 根目录。
- 每次执行前显示命令、工作目录、预计超时和输出限制，并通过 TTY 审批。
- 默认 `ask`：每次命令都询问；当前 chat 可选择允许同一工具、同一工作目录和同一精确命令再次执行；退出进程后授权失效。
- `deny` 拒绝本次执行；拒绝、取消、超时和启动失败都不产生“成功”结果。
- 记录退出码、耗时、超时/取消状态和截断标记；stdout/stderr 有独立上限，避免命令占满上下文和终端。
- 命令执行使用 workspace 作为 cwd，不允许通过 cwd 或参数绕过 workspace 边界；具体 shell 解析策略必须在实现前固定并测试。
- 测试运行属于受控命令执行的一类，必须显示完整测试命令；不得因为命令名包含 `test` 就自动放行。

## 非目标

- 不在 M3.4 引入 OS 沙箱、永久权限配置、跨进程授权或 Git 回滚。
- 不让 `-p`、`audit` 或 session 管理命令执行外部命令。
- 不把任意命令输出写入完整会话；审计只保存脱敏命令摘要、退出码、字节数、耗时和结果状态。
- 不承诺跨平台 shell 语义完全一致；Windows 与 Unix 的命令启动方式分别测试。

## 权限模型

| 模式 | 行为 |
| --- | --- |
| `ask` | 默认值，每次执行前审批 |
| `allow` | 仅当前 chat、同一工具、同一工作目录和同一精确命令免重复审批 |
| `deny` | 本次不执行并返回稳定拒绝原因 |

允许记忆不写入 session、audit 或 changes，也不允许把路径模式扩大成整个 workspace。

## 运行边界

- 默认单命令超时和输出上限必须是常量，并在结果中明确显示。
- Ctrl+C 只取消当前命令和当前轮，chat 仍可继续输入。
- 超时后尽力终止进程树；若平台无法确认子进程已退出，结果标记为 `timeout_unconfirmed`，不得报告成功。
- 命令输出统一进入紧凑工具反馈；完整输出按需截断，不把隐藏的控制序列直接写入 TTY。
- 审计错误阶段至少区分 `command_denied`、`command_timeout`、`command_cancelled`、`command_exit_nonzero` 和 `command_output_limited`。

## 验收重点

1. `-p` 不暴露 `run_command`，chat 才能看到审批。
2. `ask`、当前 chat 的精确 `allow`、`deny` 和退出后授权失效均通过测试。
3. cwd、路径边界、超时、输出上限、取消和非零退出码不会伪装成成功。
4. `go test ./...` 等测试命令必须经过同样的审批、超时、输出限制和审计链路。
5. 审计不包含 API Key、Authorization、环境变量密钥或未脱敏绝对路径。
