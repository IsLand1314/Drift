# M0.7：Provider 诊断与读取保护

M0.7 解决真实调用失败时只有模糊提示的问题，并避免把明显的二进制内容放进模型上下文。它不改变 M0.6 的 workspace、Focus、工具集合或只读边界。

## 调用流程

```text
CLI
  -> OpenAI Compatible Provider
  -> HTTP / SSE 流
  -> Agent 产生 error 事件（stage + 安全错误文本）
  -> JSONL 会话记录
  -> stderr 输出错误，命令以 1 退出
```

Provider 的内部原始错误只用于 Go 的错误链；用户看到的错误和 JSONL 都不会包含响应正文、请求体、密钥或绝对路径。

## `stage` 含义

| stage | 含义 |
| --- | --- |
| `provider_timeout` | 请求超时 |
| `provider_transport` | 无法建立或完成网络连接 |
| `provider_http` | 服务返回非 200 HTTP 状态 |
| `provider_non_sse` | 服务未返回 SSE 响应 |
| `provider_sse_invalid_json` | SSE `data:` 内容不是有效 JSON |
| `provider_sse_server_error` | SSE 中包含服务端错误对象 |
| `provider_sse_event_too_large` | 单个 SSE 事件累计超过 1 MiB |
| `provider_sse_line_too_large` | 单条 SSE 行超过 1 MiB |
| `provider_sse_read` | 读取 SSE 流失败 |
| `provider_sse_disconnected` | 流结束前未收到 `[DONE]` |

非 Provider 的 Agent 自身错误使用 `agent`。例如查看最新会话：

```powershell
Get-ChildItem .drift\sessions\*.jsonl |
  Sort-Object LastWriteTime -Descending |
  Select-Object -First 1 |
  Get-Content -Encoding utf8
```

会话文件是标准 UTF-8 JSONL（不写 BOM）。部分 Windows PowerShell 版本会把无 BOM 的 UTF-8 按系统本地编码读取，导致中文显示为乱码；查看会话时必须显式使用 `-Encoding utf8`。不要为兼容旧默认编码改写 BOM，否则会影响严格 JSONL 读取器。

其中一条错误记录的形状如下：

```json
{"version":1,"type":"error","error":"模型 SSE 流包含无效 JSON","stage":"provider_sse_invalid_json"}
```

时间字段会随实际运行写入；示例刻意省略了它。

## `read_file` 的变化

带分页参数时，工具返回实际行号范围：

```text
read_file: lines 21-40
...文件内容...
read_file: more lines available; next offset: 40
```

`offset` 依旧从 0 开始，而显示的行号从 1 开始。全文读取或已读分页行包含 NUL 字节时，工具返回 `read_file target is binary`，内容不会进入模型上下文。
