# M0.2.1 Multi-Read Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the completed M0.2 read-only loop so one task can safely read up to four workspace files within a 512 KiB aggregate budget and report unsupported broad requests clearly.

**Architecture:** Keep the existing two-provider-request shape: the first response may contain several `read_file` calls, Drift executes them sequentially, appends one assistant message plus one tool result per call, and sends one final request without tools. The Agent owns per-task call and byte budgets; the existing file tool keeps per-file path and 128 KiB protections.

**Tech Stack:** Go 1.26+, standard library, existing `llm.Client`, `tool.Read`, `httptest`.

**Spec:** `doc/m0.2-read-agent.md` and `spec/current.md`.

## Global Constraints

- Use Go 1.26+ and no new dependencies.
- Keep the runtime read-only: no write, delete, edit, exec, session, TUI, MCP or provider expansion.
- Each task makes at most two provider requests and at most four `read_file` calls.
- Each file remains limited to 128 KiB; successful file contents sent in one task must not exceed 512 KiB in aggregate.
- Reject absolute paths, traversal, symlink escapes, directories, non-regular files and oversized files exactly as M0.2 does.
- Preserve OpenAI SSE aggregation and DeepSeek `reasoning_content` replay.
- stdout contains only final model text; diagnostics stay on stderr; API keys remain environment-only.
- Commits use Chinese messages with `island` as author and committer.

## Task 1: Extend Agent Loop to bounded multi-read

**Files:**

- Modify: `internal/agent/agent.go`
- Modify: `internal/agent/agent_test.go`

**Interfaces:**

Consumes existing `llm.Client`, `tool.Read`, `llm.Message` and `llm.ToolCall`.

Produces:

~~~go
const MaxToolCalls = 4
const MaxTotalReadBytes = 512 << 10

func Run(ctx context.Context, client llm.Client, root string, prompt string, emitText func(string) error) error
~~~

- [ ] **Step 1: Write failing multi-read tests**

Add scripted-client tests with three first-turn `read_file` calls for `README.md`, `go.mod` and `spec/current.md`. Assert exactly two requests, one assistant message containing all three calls, three matching tool messages in call order, no tools in request two, and only final text emitted.

Add a test with five first-turn calls and assert a non-nil user-facing error containing `最多读取 4 个文件` and only one provider request.

Add an aggregate-budget boundary test: create four 128 KiB files to verify the exact 512 KiB boundary, retain the production defensive check, and test the over-limit branch again if the limit changes in the future.

- [ ] **Step 2: Run focused tests and verify they fail**

~~~powershell
go test ./internal/agent -run 'TestRun(MultipleReadRoundTrip|RejectsTooManyToolCalls|EnforcesAggregateReadBudget)$' -count=1
~~~

Expected: the multi-read and budget tests fail because the current loop requires exactly one tool call and has no aggregate budget.

- [ ] **Step 3: Implement bounded execution**

Define `MaxToolCalls = 4` and `MaxTotalReadBytes = 512 << 10`. On the first completion:

- `stop` with zero tool calls emits buffered text and returns;
- any non-empty tool-call list with more than four calls returns a Chinese error containing `最多读取 4 个文件`;
- every call must be named `read_file`;
- execute calls sequentially;
- append the single assistant completion message once, then append one `role: tool` message per call with its original ID;
- if one read fails, preserve the existing safe `read_file failed: ...` result and continue;
- if a successful result would exceed the aggregate budget, use `read_file failed: total read limit exceeded` for that result and continue;
- send exactly one second request with no tools.

Keep the second-turn rule: only `stop` with zero tool calls succeeds; any second-turn tool call is an error. Stream only second-turn text to `emitText`.
