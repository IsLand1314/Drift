# M4.2 多子 Agent 并行计划

## 目标

在 M4.1 生命周期内核之上支持多个独立任务并发执行，限制资源占用，并保证失败和取消隔离。

## 最小实现

1. 把 `ChildManager` 的单活动句柄改为按 `task_id` 管理的 map。
2. 通过构造参数设置并发上限；默认 chat 上限为 4，超过上限直接拒绝。
3. 保持 `TaskRun` 异步，`TaskStatus` 和 `TaskCancel` 按任务 ID 操作。
4. 复用现有 Worktree 绑定，不允许任务间共享结果或静默覆盖。
5. 主会话退出时取消并等待所有活动子 Agent。

## 验收门

- 两个任务同时进入运行；第三个超过上限被拒绝。
- 一个任务失败时另一个仍完成。
- 单独取消一个任务不影响另一个。
- 结果、错误、审计和任务 Worktree 按 ID 隔离。
- `go test ./...`、race、vet、build、提交范围 diff 检查通过。
- 真实 LLM 工具调用需在 DeepSeek 伪工具格式问题解决后另行验收。
