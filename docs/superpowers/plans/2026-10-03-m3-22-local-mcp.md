# M3.22 Local MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add explicit local stdio MCP connection, delayed discovery, per-call confirmation, and redacted auditing without altering native tool or sandbox behavior.

**Architecture:** `internal/mcp` owns validated user-authored configuration and JSON-RPC-over-stdio lifecycle. `internal/tool` adapts discovered tools into disabled `ToolSearch` entries. `internal/agent` treats them as external previewable actions; `internal/app` exposes only user-originated `/mcp` connection commands.

**Tech Stack:** Go standard library, existing `tool.Registry`, `agent.PermissionPrompt`, JSONL audit, Bubble Tea.

**Spec:** `spec/m3.22-mcp.md`

## Global Constraints

- Support only workspace `.drift/mcp.json` using local `stdio` transport.
- Do not add dependencies, remote HTTP/SSE, OAuth, marketplace installation, automatic connection, persistent MCP authorization, MCP resources, or MCP prompts.
- MCP calls always require one-time confirmation in `default`, `acceptEdits`, and `bypassPermissions`; `plan` denies them.
- Do not forward workspace content, session context, API keys, or environment values automatically.
- Audit server/tool/status/byte counts but redact arguments, output, config environment values, secrets, and absolute paths.
- Preserve existing native tools, permission rules, Bash sandbox, Git, and change-set semantics.
