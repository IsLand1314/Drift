# M0.8 Trace 可观测性实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 增加可选的 `--trace` 运行诊断，让用户能在 stderr 看到 Agent 的关键事件摘要，同时保持 stdout、Agent 行为和安全边界不变。

**Architecture:** 复用现有 `agent.Event`，在 app 编排层增加一个可选的 trace sink。Trace 只输出事件类型、已知工具名、结果字节数和错误 stage，不输出文件内容、原始参数、密钥或绝对路径；Session 仍保存完整脱敏 JSONL。

**Tech Stack:** Go 标准库 `flag`、`fmt`、`io`、`strings`，现有 `testing`、`httptest`。

**Spec:** `spec/current.md` 的 M0.8 章节；阶段说明为 `doc/m0.8-trace.md`。

## Global Constraints

- 继续使用 Go 1.26+ 和标准库，不新增依赖。
- 默认不启用 trace；不传 `--trace` 时 stdout/stderr 与现有行为一致。
- stdout 只输出最终回答；trace 只写 stderr。
- trace 不写文件内容、工具原始 arguments、API Key、Authorization、Provider 响应正文或本地绝对路径。
- Agent 请求、工具、累计结果和 workspace 只读边界保持 M0.7 行为。
- 所有行为变更先写失败测试，再写最小实现。

### Task 2: 接入 `--trace` CLI 开关

**Files:**
- Modify: `internal/app/app.go`
- Modify: `internal/app/app_test.go`

**Interfaces:**
- Consumes: `newTraceSink(io.Writer)` from Task 1.
- Produces: `--trace` flag and unchanged `Run` return/output contract.

- [ ] **Step 1: Write the failing integration test**

复用现有本地 SSE 测试服务，运行参数增加 `--trace`，断言最终回答仍在 stdout、trace 出现在 stderr、正常模式仍保持 stderr 为空。测试名为 `TestRunTraceKeepsAnswerOnStdout`。

- [ ] **Step 2: Run the test to verify it fails**

```powershell
go test ./internal/app -run TestRunTraceKeepsAnswerOnStdout -count=1
```

Expected: FAIL because `--trace` is not registered。

- [ ] **Step 3: Write the minimal implementation**

在 `Run` 中注册：

```go
trace := flags.Bool("trace", false, "将运行过程摘要输出到 stderr")
```

Event sink 仍先追加 Session；当 `*trace` 为 true 时再调用 trace sink。不要把 trace 文本写入 stdout，也不要改变 Session 内容。

- [ ] **Step 4: Run focused integration tests**

```powershell
go test ./internal/app -run "TestRunTraceKeepsAnswerOnStdout|TestRunDirectAnswer|TestRunReadRoundTrip" -count=1
```

Expected: PASS；非 trace 测试的 stderr 仍为空。
