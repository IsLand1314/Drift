# M1.7：单轮取消设计

## 1. 背景与目标

当前 `drift chat` 使用进程级 Context。用户按下 Ctrl+C 时，正在进行的模型请求和整个 chat 进程一起结束，无法继续复用已经建立的会话。M1.7 只解决“取消当前轮”的生命周期问题，不引入 TUI、输入队列或并发工具。

目标：

- Ctrl+C 在模型流或工具执行期间只取消当前轮；
- chat 进程继续运行并显示新的输入提示；
- 已完成的历史消息、完整会话快照和 Token 统计保持一致；
- 被取消轮次不写入半截 assistant 消息；
- 取消原因进入脱敏审计，但不保存提示词、回答正文或工具参数。

## 2. 非目标

- 不实现完整终端行编辑、多行输入、输入队列和 TUI；
- 不实现后台任务、暂停/恢复单轮、自动重试；
- 不改变现有 workspace、只读工具、Provider 协议和上下文上限；
- 不把 Ctrl+C 变成文件操作或权限确认机制。

## 3. 用户行为

正常请求期间：

```text
❯ 分析整个项目
● 正在输出……

^C
已取消当前轮；会话仍可继续
────────────────────────
❯ 换个问题
```

空闲等待输入时，Ctrl+C 保持现有退出行为，进程以退出码 130 结束。取消只对当前正在执行的 `runner.RunEvents` 或其下游 Provider/工具调用生效。

## 4. 生命周期设计

```text
chat 进程 Context（只负责 chat 生命周期）
        │
        ├── 当前轮 Context（每条用户输入创建）
        │       ├── Provider SSE 请求
        │       └── 只读工具执行
        │
        └── 当前轮结束/取消后释放
```

- `runChatLoop` 为每条普通输入创建 child context；
- Signal 处理器只向当前轮 cancel 函数发送取消；
- 当前轮返回 `context.Canceled` 时，Agent 丢弃尚未提交的本轮 assistant 内容；
- chat 层把取消转换为提示消息并继续循环；
- `/status`、`/clear`、`/compact` 和退出命令不启动当前轮 Context。

实现必须保证同一时间最多存在一个活动轮次，因此不需要并发访问 Runner 消息列表的锁。

## 5. 会话与 Token 规则

- 取消前已经存在的 Runner 消息不变；
- 取消轮的 user 消息不写入完整会话快照，避免恢复后出现没有 assistant 结果的半轮；
- 取消轮已发生的 Provider usage 不计入会话累计统计；
- 取消不清空历史 Token 统计；
- `/clear` 仍同时清空消息和 Token 统计；
- `--no-session` 继续只保留当前进程内存，不写完整会话。

## 6. 审计与输出

新增稳定错误 stage：`agent_cancelled`。

审计只记录：

- `type=error`；
- `stage=agent_cancelled`；
- 时间和必要的结束原因。

不记录取消时的提示词、已输出回答正文、文件内容或原始工具参数。stdout 保留已经流出的回答片段，随后输出取消提示；完整快照不保存这段半截回答。

## 7. 错误边界

- Provider 返回普通错误：维持现有错误处理，不视为取消；
- `context.Canceled` 且由当前轮 cancel 触发：转成 `agent_cancelled`，chat 继续；
- chat 主 Context 被外部关闭：保持进程退出行为；
- 保存旧快照失败：不覆盖旧快照，提示保存失败并结束当前轮；
- 取消发生在工具执行中：工具必须收到 Context 并尽快返回，不启动新的工具调用。

## 8. 验收标准

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| AC-M17-001 | Provider 流式输出期间按 Ctrl+C | 当前轮结束，chat 返回新提示符，进程不退出 |
| AC-M17-002 | 工具执行期间按 Ctrl+C | 工具收到取消，后续工具不再执行，chat 可继续 |
| AC-M17-003 | 取消后检查完整会话 | 取消轮的 user/assistant 半轮不进入快照，旧消息可恢复 |
| AC-M17-004 | 取消后查看 `/status` | 历史 Context 和 Token 统计保持不变 |
| AC-M17-005 | 取消后查看 JSONL | 出现 `agent_cancelled`，不出现正文、原始参数或文件内容 |
| AC-M17-006 | 空闲时 Ctrl+C | chat 以退出码 130 退出，行为不回归 |
| AC-M17-007 | 自动测试与构建 | `go test ./...`、`go vet ./...`、构建和 `git diff --check` 全部通过 |

## 9. 交付边界

M1.7 完成后，Drift 具备可持续的单进程交互生命周期：用户可以取消单轮但保留会话。完整 TUI、输入编辑和后台任务继续留到后续阶段，避免把终端 UI 与 Agent 生命周期同时引入。
