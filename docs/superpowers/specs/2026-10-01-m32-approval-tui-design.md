# M3.2 审批选择器与运行反馈设计

## 目标

将 M3.1 的确认式 `write_file` 从“输入 y/N”提升为紧凑的终端审批面板，并统一读写工具的进度、耗时和完成状态；保持当前只读边界、workspace 路径校验和本地变更记录不变。

## 范围

### 审批选择器

仅在真实 TTY 中启用交互选择器；重定向、测试和非终端输入继续使用纯文本兼容路径。

审批面板显示：

```text
WriteFile command

  <workspace-relative-path>

  This command requires approval

❯ 1. Yes
  2. Yes, and don't ask again for this pattern
  3. No
```

键盘行为：

- ↑ / ↓ 或 `1` / `2` / `3` 选择；
- Enter 确认；
- Esc / Ctrl+C 等同于拒绝当前操作；
- 面板不要求用户输入 `y`，选择完成后不保留选择器底部的操作提示。

M3.2 的第二个选项只在当前 chat 进程内记忆，按“工具名 + 操作类型 + 受保护的路径模式”匹配；不写入会话快照、审计 JSONL 或 `.drift/changes`。退出进程后失效。路径模式不得扩大 workspace 边界，也不得绕过既有安全校验。

### 紧凑运行反馈

TTY 中将原始工具行归一为短状态：

```text
● Write hello.txt ...
✓ Write hello.txt (11 bytes) · 0.2s
● Read README.md ...
✓ Read README.md · 8.2 KB · 0.4s
```

- 处理中显示灰色状态和实时耗时；完成显示成功色和耗时；失败显示错误色和简短安全原因；
- 写入审批只展示操作、相对路径和字节数，不展示完整 diff 头；完整 diff 继续保存到 `.drift/changes`；
- 非 TTY 保留稳定纯文本，不输出 ANSI；`--trace` 继续提供完整事件级诊断；
- 同一轮多个工具调用不重复渲染冗余段落，保持“请求 → 结果”顺序。

### 失败反馈

`write_file` 预检失败时，Agent 返回给模型的错误仍需脱敏，但 TTY 同时显示用户可理解的原因（例如“目标父目录不存在”）。模型可以继续完成解释，但不应把 Drift 源码作为默认诊断路径；system context 要求写入失败后先说明失败原因，不读取实现文件来解释运行时行为。

## 非目标

- 不做完整全屏 TUI、滚动 viewport、多行编辑或历史搜索；
- 不做永久权限配置、权限配置文件或跨进程授权；
- 不自动创建目标父目录；
- 不改变 `-p` 的只读注册表；
- 不引入删除、命令执行、测试运行、OS 沙箱或 Git 回滚。

## 验收标准

- `chat` 中写入审批可只用方向键和 Enter 完成；拒绝和 Ctrl+C 均不修改目标文件；
- “本次允许 / 当前模式允许 / 拒绝”三种结果在审计中保持可区分；
- 审批完成后选择器消失，只保留紧凑结果和耗时；
- 读写工具的 TTY 反馈包含开始、完成/失败和耗时；非 TTY 输出无 ANSI；
- 预检失败能显示安全、明确的用户提示，且不会泄露绝对路径、密钥或完整文件内容；
- 自动化测试覆盖选择移动、确认、拒绝、会话内记忆、取消、渲染和错误路径；
- `go test ./... -count=1`、`go vet ./...`、`go build -o .codex-temp\drift-m32.exe ./cmd/drift`、`git diff --check` 全部通过。
