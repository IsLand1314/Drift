# M5.2：Codex 登录态 Provider

## 目标

让 Drift 能通过官方 `codex app-server` 使用当前机器上的 Codex 登录态，不把 ChatGPT/Codex token 当作 API Key 处理，也不读取或复制 `.codex` 私有凭据文件。

## 第一阶段边界

- `config.toml` 支持 `protocol = "codex"`。
- Drift 启动 `codex app-server --listen stdio://`，使用 JSON-RPC 初始化和文本请求。
- 复用 Codex 官方登录状态；`codex login status` 未登录时安全失败。
- 第一阶段只支持文本回答；不向 app-server 委托 Drift 的文件工具、Bash、MCP、审批或沙箱。
- Drift 的 `-p` 和 `chat` 继续保留自身会话、审计和取消语义；Codex Provider 不得执行宿主命令。
- 不实现 OAuth 登录 UI、不解析 `.codex` token 文件、不把 token 写入 `auth.json`。

## 配置

```toml
[[providers]]
name = "codex"
protocol = "codex"
model = "gpt-5.6-luna"
codex_home = "C:/Users/千/.codex"
```

`codex_home` 只作为 Codex 子进程的 `CODEX_HOME` 环境提示；凭据由 Codex 自己管理。

## 安全边界

1. 不读取、打印或持久化 Codex 凭据。
2. app-server 的 stderr 不进入 Drift stdout、session 或审计正文。
3. 请求包含 Drift 工具定义时，第一阶段拒绝并提示暂不支持，避免出现两套工具执行链。
4. 子进程随请求上下文退出，超时或取消时终止进程树。
5. app-server JSON-RPC 错误只返回稳定错误阶段，不回显 token、请求正文或远端响应。

## 验收

- `codex login status` 已登录时，Codex Provider 能完成一次文本请求。
- 未登录、命令不存在、初始化失败、超时和取消均安全失败。
- 工具请求被拒绝且不会执行工具。
- 模型增量事件正确映射到 `llm.StreamEvent.Text`。
- `go test ./...`、`go vet ./...`、`go build ./cmd/drift` 通过。
