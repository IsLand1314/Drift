# M3.27：Git Worktree 隔离最小闭环

## 目标

为未来的 Agent/任务隔离提供一个受控的 Git linked worktree 生命周期：

```text
drift git worktree create <name> [base] --yes
drift git worktree list
drift git worktree remove <name> --yes
```

工作目录固定在 `<repository>/.worktrees/<name>`。普通文件发现、写入和命令工具继续跳过或保护 `.worktrees`；worktree 生命周期只能由专用 Git 能力管理。

## 与已有能力的边界

- 已有 `GitRevert`：对当前干净 worktree 的一个已提交 commit 创建反向提交；不创建 linked worktree。
- 本阶段：创建/列出/删除 linked worktree；不自动把 Agent 调度到 worktree。
- 不实现：自动合并、冲突解决、远程 worktree、强制删除、`reset --hard`、`git clean` 或多 Agent 协调。

## 安全规则

1. 仅接受单段 `[A-Za-z0-9][A-Za-z0-9._-]{0,63}` 名称，拒绝路径分隔符、`.`、`..` 和路径逃逸。
2. 基础 revision 用 `git rev-parse --verify <base>^{commit}` 解析，不通过 shell 拼接执行。
3. `.worktrees` 不得是符号链接；目标已存在时拒绝覆盖。
4. 创建和删除均要求 CLI 显式 `--yes`。
5. 删除不使用 `--force`，Git 检测到未提交修改时失败并保留 worktree。

## TDD 与验收

```text
go test ./internal/git -run 'Test(CreateList|CreateWorktree)' -count=1
go test ./internal/app -run TestGitWorktreeLifecycleRequiresConfirmation -count=1
go test ./... -count=1
go vet ./...
go build ./cmd/drift
git diff --check
```

通过条件：创建后的文件与指定 revision 一致；列表能看到 managed worktree；未确认创建被拒绝；删除后目录消失；非法名称和重复目标被拒绝；全量测试、静态检查、构建和 diff 检查通过。
