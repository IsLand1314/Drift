# M3.30：Worktree 自动合并与冲突安全处理

## 目标

把已提交的 managed worktree 分支安全合并回主工作区，覆盖主工作区被用户修改、Worktree 未提交、无冲突合并和冲突四种路径。

## 规则

1. 新建 managed worktree 使用 `drift/<name>` 分支；旧 detached worktree 只允许列出、切换和人工处理，不自动猜测分支。
2. 主工作区必须干净，Worktree 必须干净；不自动 stash、reset 或 clean。
3. 合并前做冲突预检查；检测到冲突时不执行主工作区合并，返回冲突文件。
4. 无冲突时使用非强制的 `git merge --no-ff --no-edit`，生成 merge commit。
5. 合并成功后保留源 Worktree，不自动删除。
6. 创建和合并需要显式 `--yes`。

## 命令

```text
drift git worktree create <name> [base] --yes
drift git worktree merge <name> [-w <workspace>] --yes
```

## 验收

```text
go test ./internal/git -run 'Test(Create|Merge)' -count=1
go test ./internal/app -run TestGitWorktree -count=1
go test ./... -count=1
go vet ./...
go build ./cmd/drift
git diff HEAD^ HEAD --check
```

通过条件：主工作区或源 Worktree 脏时拒绝；无冲突时产生 merge commit；冲突时主工作区 HEAD 和文件内容保持不变并返回冲突路径；不使用强制 Git 命令。
