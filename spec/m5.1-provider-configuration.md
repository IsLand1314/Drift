# M5.1：Provider 配置与认证分离

## 目标

把 Drift 的用户运行配置分成三个职责明确、只有一个权威位置的文件：行为设置、Provider/模型定义和认证凭据。支持多个 Provider 的启动选择与非交互默认选择，同时不让 API Key 进入 workspace、会话、审计或 Git。

本阶段不采用全局/项目/本地多层覆盖。每个文件只有一个用户级位置，由 `os.UserConfigDir()` 解析后追加 `Drift`：Windows 通常为 `%APPDATA%\\Drift`，Linux/macOS 使用各自的用户配置目录。

```text
<user-config-dir>/Drift/
├── settings.toml  # 行为与默认策略
├── config.toml    # Provider、模型、协议和端点
└── auth.json      # API Key；以后可扩展 OAuth
```

workspace 的 `.drift/` 继续只保存 session、audit、change set、权限规则和任务状态。模型工具、Bash、MCP 不得读取或修改用户配置目录。

## 文件职责与格式

| 文件 | 格式 | 内容 | 密钥 | Git |
| --- | --- | --- | --- | --- |
| `settings.toml` | TOML | 默认 Provider、权限模式、沙箱模式、TUI 和 chat 默认行为 | 禁止 | 永不在项目中出现 |
| `config.toml` | TOML | Provider 别名、协议、端点、模型和上下文限制 | 禁止 | 永不在项目中出现 |
| `auth.json` | JSON | Provider 别名对应的 API Key；未来 OAuth 凭据 | 允许 | 永不在项目中出现 |

TOML 用于人工维护的设置和 Provider 列表，避免 YAML 的缩进语义；JSON 用于结构严格、未来会被程序写入的认证数据。仅引入一个 TOML 解析依赖；`auth.json` 使用 Go 标准库。

所有三个文件使用 `version = 1`（JSON 为 `"version": 1`）。未知字段、重复 Provider 名、空白名称、未知协议、非法模式或不安全 URL 都是启动前配置错误；错误不得回显密钥或认证文件正文。

## settings.toml

第一版只允许已有运行能力的默认值，不新增安全能力：

```toml
version = 1

default_provider = "deepseek"
permission_mode = "default"
sandbox_mode = "auto"
tui_mode = "main"

[chat]
auto_compact = true
```

- `default_provider` 必须引用 `config.toml` 中的 Provider 名。
- `permission_mode` 只允许 `default`、`acceptEdits`、`plan`。`bypassPermissions` 不允许持久化为启动默认值，必须由明确的命令行或交互选择开启。
- `sandbox_mode` 复用现有 `off`、`auto`、`required` 契约。
- `tui_mode` 当前只允许 `main`；`full` 预留但本阶段不实现。
- `chat.auto_compact` 映射已有上下文压缩开关；缺失时保留现有默认行为。

## config.toml

每个 `[[providers]]` 是一个可选择的运行 profile。`name` 是稳定 ID，同时关联 `auth.json` 中的密钥。

```toml
version = 1

[[providers]]
name = "deepseek"
protocol = "openai-compat"
base_url = "https://api.deepseek.com"
model = "deepseek-chat"
api_key_env = "DEEPSEEK_API_KEY"
context_window = 128000
max_output_tokens = 8192

[[providers]]
name = "anthropic"
protocol = "anthropic"
base_url = "https://api.anthropic.com"
model = "claude-sonnet-4-6"
api_key_env = "ANTHROPIC_API_KEY"
context_window = 200000
max_output_tokens = 32000
```

- `protocol` 第一版只支持 `openai`、`openai-compat`、`anthropic`。它选择已有 Provider adapter；不新增第三方协议。
- `base_url` 必须是无用户名、密码、查询参数、片段的 HTTP(S) URL。非 loopback 主机必须使用 HTTPS。
- `model`、`context_window`、`max_output_tokens` 必须非空/正数，后两者仅供请求预算与展示使用。
- `api_key_env` 是可选的环境变量回退名称，不含密钥。
- 不支持自定义 headers、shell 命令取密钥、配置内 OAuth 或配置内 API Key。

## auth.json

认证由当前用户维护，第一版只读；写入式 `/login` 与 OAuth 留给后续阶段。其最小格式为：

```json
{
  "version": 1,
  "providers": {
    "deepseek": { "type": "api_key", "key": "sk-..." },
    "anthropic": { "type": "api_key", "key": "sk-..." }
  }
}
```

- `providers` 的 key 必须匹配 `config.toml` 的 Provider 名；未配置 Provider 的认证条目被忽略但不报出其值。
- `type` 第一版只能为 `api_key`；空 key 是错误。
- Unix 新建文件权限为 `0600`；Windows 使用当前用户独占 ACL。读取时若权限/ACL 不满足安全要求，拒绝使用该文件。
- 敏感值不得出现在 stderr、trace、audit、session、change set、工具输出或错误包装中。

## Provider 与认证解析

选择顺序：

```text
--provider <name>
  → 直接选择指定 profile
未指定且只有一个 profile
  → 自动选择
未指定且 chat 有多个 profile
  → 启动 Provider 选择器，default_provider 默认高亮
未指定且 -p 有多个 profile
  → 使用 default_provider；缺失或非法则拒绝启动
```

单次命令的密钥优先级：

```text
--api-key
  > auth.json 中所选 Provider 的 api_key
  > config.toml 中 api_key_env 指向的环境变量
```

`--model`、`--base-url` 仅覆盖本次请求的 profile 值；不会写回配置。`--permission-mode`、`--sandbox` 同理覆盖 `settings.toml` 默认值。选中的 Provider 名和模型名可写入审计；URL、API Key 和 `auth.json` 内容不得写入。

为不破坏既有用户，配置目录中不存在 `config.toml` 时继续使用现有 `openai`/`anthropic` + 环境变量/`.env` 启动路径，并输出一次迁移提示。存在 `config.toml` 时不再读取 workspace `.env`。

## 安全边界

1. 用户配置目录不属于 workspace；`Glob`、`Grep`、`ReadFile`、写入工具、Bash、MCP 和子 Agent 均不能通过 Drift 获取其内容。
2. `auth.json` 绝不提交。项目如需说明，只提交无密钥文档示例，不提交空 `auth.json` 占位文件。
3. Provider URL 和模型参数来自用户配置，而不是受检出仓库控制的 `.drift` 文件。
4. 配置载入失败不得回退到另一个 Provider 或静默使用错误密钥。
5. 本阶段不改变权限审批、OS 沙箱、workspace 边界和 MCP 审批链路。

## 非目标

- 不实现配置分层、项目覆盖、热加载或运行时编辑配置。
- 不实现 OAuth、订阅登录、密钥管理器、`/login`、`/logout` 或 `drift auth set`。
- 不实现 YAML 配置、Hooks、MCP HTTP、Provider 自定义 header 或命令式 secret resolver。
- 不改变或自动解析模型返回的伪工具调用；原生 Tool Call 恢复属于后续独立阶段。
