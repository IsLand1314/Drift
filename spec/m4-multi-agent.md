# M4：多 Agent 交付主线

## 阶段

| 阶段 | 目标 | 必须验收 |
| --- | --- | --- |
| M4.1 | 单子 Agent 闭环 | 创建、运行、取消、超时、回收；成功/失败/取消/超时回传；主会话不崩溃；审计完整 |
| M4.2 | 多子 Agent 并行 | 并发确实发生；Worktree 互不污染；单个失败不拖垮全部；并发上限和取消机制 |
| M4.3 | 任务依赖和状态同步 | DAG、`pending/blocked/running/completed/failed/cancelled` 状态转换；重启可恢复 |
| M4.4 | 自动合并与冲突协调 | 隔离 Worktree；无冲突自动合并；冲突进入队列；合并前后验证 |
| M4.5 | 消息和结果汇总 | 消息含发送者、接收者、时间和任务 ID；结果不重复、不丢失；主 Agent 可汇总 |

## 每阶段双层验收

第一层是确定性验收：单元测试、集成测试、并发/超时/取消/重启测试、文件和 Git 状态检查。第二层是独立 LLM 验收：使用新上下文和只读权限，只读取需求、diff、测试结果和运行结果，不得修改代码或审批自己的改动。

独立验收 Agent 的结论只能是：

- `PASS`：允许进入下一阶段；
- `FAIL`：必须修复后重新验收；
- `BLOCKED`：缺少环境、配置或外部条件。

每阶段固定交付：代码变更、阶段测试结果、LLM 验收报告、未解决问题、是否允许进入下一阶段。
