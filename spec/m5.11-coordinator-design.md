# M5.11：Coordinator 调度策略设计

## 目标

在现有 Plan、Task、Child Agent 和 Worktree 能力之上增加一个确定性 Coordinator，负责任务排队、依赖调度、并发限制、失败恢复和合并协调。Coordinator 不绕过权限、沙箱、审批或审计。

## 边界

LLM 负责理解需求、生成结构化 Plan 和任务描述；Coordinator 负责执行状态机。Coordinator 不直接读取或修改文件，不直接执行 Bash，不自行调用 MCP。

```text
用户需求 → LLM Planner → Plan/DAG → Coordinator → TaskRunner → 子 Agent
                                           ↓
                                  Worktree / 审批 / 沙箱 / 审计
```

## 状态机

```text
pending → ready → running → completed → merge_pending → merged
                       ├→ failed
                       ├→ timeout
                       ├→ cancelled
                       └→ conflict → conflict_waiting → merged
```

当依赖任务进入 `failed`、`timeout`、`cancelled` 或 `blocked` 时，后续任务进入 `blocked`。已经完成或已经合并的任务不因 Coordinator 取消而回滚。

## 调度规则

- 只有所有依赖完成的任务才能进入 `ready`；
- 默认最大并发数为 2，配置范围为 1–4；
- 同优先级按依赖数量和创建顺序调度；
- 第一版不做抢占、动态资源估算或复杂评分；
- 每个写入任务使用独立受管 worktree；
- 无冲突自动合并，有冲突进入 `conflict_waiting`，只允许显式 `TaskMerge` 重试；
- 不自动执行 `reset`、`stash`、`clean` 或删除用户改动。

建议配置：

```toml
[coordinator]
max_concurrency = 2
max_retries = 1
retry_backoff_ms = 1000
```

## 失败和重试

只重试暂时性错误：Provider timeout、子 Agent timeout、临时网络错误和子进程启动失败。用户拒绝、权限拒绝、沙箱拒绝、参数错误、依赖失败和 worktree 冲突不自动重试。

Coordinator 取消时停止派发新任务，取消所有运行中的子 Agent，等待进程树回收，并将未开始和运行中的任务分别标记为 `cancelled`。

## 实现阶段

### M5.11-A：确定性调度器

- ready queue；
- DAG 依赖校验；
- 并发额度；
- 状态持久化；
- 复用现有 `TaskRun`、`TaskStatus`、`TaskCancel` 和 `TaskMerge`。

### M5.11-B：并发与取消

- 多任务真正并行；
- Coordinator 级取消；
- 超时和进程回收；
- 生命周期审计。

### M5.11-C：失败恢复

- 可重试错误分类；
- 最大重试次数和退避；
- 失败依赖自动阻塞；
- 重新规划入口。

### M5.11-D：Worktree 协调

- 完成后自动合并；
- 冲突队列；
- 合并失败恢复；
- 主工作区保护。

### M5.11-E：LLM 接入

- `PlanExecute` 委托 Coordinator；
- 必要时增加 `CoordinatorStatus` 和 `CoordinatorCancel`；
- 不新增绕过权限或沙箱的执行路径。

## 验收矩阵

- 单任务成功；
- 两个无依赖任务并行成功；
- 有依赖任务按序执行；
- 前置失败导致后置 `blocked`；
- 独立任务互不影响；
- 单任务取消和 Coordinator 全局取消；
- 超时与进程树回收；
- worktree 无冲突自动合并；
- worktree 冲突进入 `conflict_waiting`；
- 重试成功与重试次数耗尽；
- 会话恢复后继续调度；
- 真实 DeepSeek 双任务链路通过。

## 非目标

- 不实现远程 Coordinator；
- 不实现跨机器调度；
- 不引入复杂的 Agent 评分或自主资源管理；
- 不在本阶段扩展 MCP Server 或新的 OS 沙箱后端。
