# M4.4：子 Agent Worktree 自动合并与冲突协调

## 目标

子 Agent 完成后由主 Agent 自动尝试合并；冲突只进入内存队列，不修改主工作区，不静默覆盖用户内容。合并复用既有 `MergeWorktree` 的干净检查和冲突预检。

## 规则

1. 只有已完成且绑定受控 `.worktrees/<name>` 的任务才触发自动合并。
2. 主工作区或源 Worktree 脏时直接拒绝，不 stash、reset、clean 或删除文件。
3. 无冲突时使用非强制合并并记录 `BeforeHEAD/AfterHEAD`。
4. 冲突时记录任务 ID、Worktree 和冲突路径到 `MergeQueue`，主工作区 HEAD 和文件保持不变。
5. 解决冲突并提交源 Worktree 后，可按任务 ID 重试；成功后从队列移除。

## 持久化状态

任务结果保留原有 `completed` 状态，另记录：

- `merge_status`: `merged`、`conflict` 或 `failed`；
- `merge_commit`: 成功合并后的 HEAD；
- `merge_conflicts`: 冲突文件列表。

## 不做的事

- 不自动猜测冲突解决方案；
- 不自动删除源 Worktree；
- 不执行强制 Git 操作；
- 不把真实 LLM 工具调用兼容性问题伪装成通过。
