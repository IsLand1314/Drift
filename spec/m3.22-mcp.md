# M3.22：本地 stdio MCP 安全闭环

## 目标

为 Drift 增加用户显式控制的本地 stdio MCP 连接、工具发现、调用审批和脱敏审计。MCP 连接不是 Bash 沙箱的替代，也不能获得 Drift 的 workspace 权限、会话正文或密钥。

## 角色边界

Drift 在本阶段只实现 MCP Host/Client：由 Drift 主进程连接用户配置的外部 MCP Server，并把其工具包装成内部工具。Drift 不监听 MCP 端口、不提供 MCP Server endpoint，也不接受其他宿主的入站 MCP 会话。`internal/mcp.Server` 仅表示外部 Server 的连接配置，不是 Drift 的 Server 实现。

## 范围

### 配置与连接

- 只读取 workspace 的 `.drift/mcp.json`；该文件由用户维护，普通 Agent 文件工具不得修改它。
- 每个 server 仅支持 `stdio`，字段为稳定的 `name`、`command`、`args` 和可选 `env` 引用名；配置中不保存密钥值。
- 仅用户通过 CLI 参数或 `/mcp connect <name>` 发起连接；模型不能自行启动、停止、安装或重连服务。
- M3.22 不支持 HTTP、SSE、OAuth、远程发现、市场安装、自动连接或跨 workspace 共享配置。
- 服务进程是外部能力，不宣称受到 `Bash` 的一次性 OS 沙箱保护；若未来需要网络隔离或密钥代理，应单独设计 sandbox-runtime。

### 发现与工具加载

```text
用户连接指定 server
  -> MCP initialize + tools/list
  -> 保存受限摘要（server、名称、描述、输入 schema）
  -> ToolSearch 搜索摘要
  -> 模型显式 load
  -> 下一次请求才公开完整 schema
```

- MCP 工具模型名称固定为 `mcp__<server>__<tool>`，避免覆盖内建工具。
- `ToolSearch` 的结果只包含可调用名称、类别 `mcp` 和描述；未 load 的 MCP 工具不能执行。
- schema、单个响应和累计输出必须受既有请求/字节预算限制。

### 权限与安全边界

| 权限模式 | MCP 调用 |
| --- | --- |
| `default` | 每次弹出单次确认 |
| `acceptEdits` | 每次弹出单次确认 |
| `plan` | 拒绝，不连接以外的调用 |
| `bypassPermissions` | 每次仍弹出单次确认 |

- MCP 的副作用不可由 schema 可靠推断，因此不支持持久化 allow 规则，也不允许 `bypassPermissions` 跳过确认。
- 确认仅允许本次 `server + tool + 参数摘要` 调用；取消、拒绝、协议错误与超时均不执行重试。
- Drift 不把 workspace 根路径、文件内容、完整历史消息、环境变量值或 API key 自动传给 MCP server。
- MCP tool output 是不可信数据，永远不能作为系统指令或权限依据。

### 审计

- 连接和调用均写入现有 JSONL 审计，包含 MCP server、工具、阶段、审批结果、执行状态、持续时间和结果字节数。
- 参数、返回正文、配置环境变量、错误中的凭据及绝对路径继续使用现有脱敏规则，不写入 JSONL。
- 至少区分 `connected`、`connection_failed`、`denied`、`cancelled`、`timeout`、`protocol_failed`、`success`。

## 非目标

- 不实现远程/云沙箱、HTTP/SSE MCP、MCP marketplace、OAuth、MCP 资源/提示词、并行 server、持久连接恢复、自动工具安装或持久化 MCP 授权。
- 不改变现有内建工具、权限规则、沙箱模式、Git 回滚或 change set 语义。
