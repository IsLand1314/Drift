# M5.11 Coordinator 验收记录

日期：2026-10-04

## 实现范围

- `PlanExecute` 在聊天注册表存在 Coordinator 时委托 Coordinator；无 Coordinator 的测试宿主保留原有回退路径。
- Coordinator 负责依赖就绪、最大并发、取消、超时预算传递、暂时性错误重试、失败依赖阻塞和 Worktree 合并回写。
- 合并仍由现有 `TaskMerger`/`MergeQueue` 执行；Coordinator 不直接执行 Git、Bash、文件工具或 MCP。
- 会话任务快照继续使用既有 `TaskRegistry.ExportTasks`/`RestoreTasks`，Coordinator 返回的状态会写回同一状态存储。

## 确定性 TDD 验收

命令：

```text
go test ./internal/coordinator ./internal/tool ./internal/app -count=1
go test -race ./internal/coordinator ./internal/tool -count=1
go test -race ./... -count=1
go test ./... -count=1
go vet ./...
go build -o .codex-temp\drift-m511.exe ./cmd/drift
```

结果：上述针对性测试、全量 race、全量测试、vet 和 build 均通过。

覆盖项：

- 单任务完成和确定性依赖阻塞；
- 两个并发槽位上限；
- Coordinator 全局取消，迟到的子进程结果不会覆盖 `cancelled`；
- `RunWithTimeout` 将计划超时预算传给 TaskRunner；
- 超时/暂时性失败重试，重试耗尽后失败；
- 失败依赖的传递性阻塞；
- Worktree merge 成功、冲突记录和 workspace 根路径传递；
- `Restore` 将中断中的 `running/in_progress` 恢复为 `pending`；
- PlanExecute 委托 Coordinator，结果写回 TaskRegistry。

## 真实 LLM 验收

使用 workspace `.drift/config.toml` 中的 DeepSeek Provider 运行了两次脱敏探测：

1. `-p` 只读模式：模型只能看到 Glob/Grep/ReadFile，明确报告没有 Plan/Task 工具。该结果是能力选择限制，不是 Coordinator 运行时失败。
2. `chat` 原生工具链：模型返回了不兼容的伪工具调用格式，进程以 `agent: 模型返回了不兼容的伪工具调用格式` 结束。

因此真实 LLM Coordinator 门禁为 **BLOCKED**，不能把确定性测试替代为 PASS。阻塞项是当前 DeepSeek 工具调用协议兼容性；修复原生 Tool Call/模型协议后，应重新运行：

```text
PlanUpdate → ExitPlanMode → PlanExecute → TaskStatus
```

并记录两个无依赖任务和一条依赖链的实际状态。
