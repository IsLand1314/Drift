# M5.10：多 Agent 可靠性

## 范围

补齐已有子 Agent、任务 DAG 和 worktree 执行链路的失败状态闭环，不引入 Coordinator 调度器。

## 行为

- 并发上限、取消、超时和子进程回收保持现有语义；
- 子 Agent 启动失败或运行失败时，任务进入 `failed` 并记录原因；
- 前置任务失败、取消、超时或阻塞时，依赖任务进入 `blocked`；
- worktree 合并冲突保持 `conflict`，只能通过显式 `TaskMerge` 重试；
- PlanExecute 传递结构化任务的 `description` 给子 Agent，避免只有标题导致执行意图丢失；
- 失败不自动宣称计划完成。

## 验收

- TDD 覆盖成功、失败、取消、超时、依赖阻塞和合并冲突；
- `go test ./... -count=1`、`go vet ./...`、`go build ./cmd/drift` 通过；
- 真实 Provider 链路完成至少两个任务状态检查；
- 不记录 API 密钥，临时 worktree 和审计证据在验收后清理。
